## 2. 当前有效状态与项目依据

- schema 为 `3.2`；`change-0.md`、completed initial 证据与
  `effective-requirements.md` 连续一致，编号记录只有 0。
- `execution/change-1/` 是下一连续且唯一活动保留号；规划前工作区为干净
  `main@4b305b2…`，没有用户改动或未知 overlap。
- Poker 缓存当前用 `width: min(28rem, calc(100% - 13rem))` 和固定负 margin，无法根据
  实际缓存面值节点数量分配间距；原始 FR-025 已要求数量行距紧凑，但现有 CSS 未落实。
- 行动/待办背景只覆盖 `small` 等部分元素；资产标签和数值拥有更高或独立选择器颜色，
  因而在强调填充下对比不足。
- 手机 `.table-seats` 同时是横向滚动和视觉裁剪所有者，现有上下 padding 小于卡片阴影
  外延，导致阴影仍会被裁剪。
- 主应用和管理员应用各自维护单一 `notice` 字符串并在多个布局位置渲染；共享 UI 层可
  提供不含业务规则的 toast provider、队列和 portal。

## 3. 影响分析与全局设计

1. 在共享 UI 层建立有界 transient toast provider。入队使用稳定 ID，数组前插保证最新
   在上；每项维护独立约 5 秒计时器，关闭按钮清理计时器并移除。provider 通过 portal
   固定在视口左上角，子页面只获得 `pushNotice(message)`，空字符串不入队。
2. 主应用、管理员应用、Poker/Avalon 房间和登录接管不再传递/渲染布局内 notice；字段级
   校验、持续信任警告和确认对话框不是瞬时操作反馈，继续保留原上下文位置。
3. Poker 玩家卡使用明确的“头像 + 身份块 + 资产块 + 徽标”网格；在线状态放入身份块，
   同时缩小 padding、头像和最小卡宽。行动/待办选择器显式覆盖所有文本 token，并保留
   本人边框与非颜色状态。
4. felt 缓存左右贴合安全边距并预留总额/清空列。筹码轨道接收当前不同面值节点数 CSS
   变量，以等分网格定位节点；首项靠左、末项靠右、中间居中，使有限宽度自动产生均匀
   重叠而不裁剪端点。数量文字使用单独紧凑行高。
5. 手机轨道扩大上下安全 padding，并以较小、有界阴影配合卡片压缩；几何断言比较卡片
   阴影/焦点/庄家安全边界与滚动盒，而不是仅检查页面宽度。

不涉及数据迁移、公共 API、服务授权、游戏规则、资产、秘密投影或运行时依赖。回滚只需
恢复 Web 组件、样式与 E2E；正式发布仍在变更冻结和提交后的独立运维步骤执行。

## 5. 跨阶段依赖与兼容约束

- 服务端仍是房间、行动者、下注、控制租约、资产与秘密的唯一权威；toast、颜色和缓存
  布局只表达现有结果，不产生命令或业务状态。
- 缓存继续是本机未确认草稿，显示条件、失效清空、金额校验和提交命令保持不变。
- 私牌、Avalon 角色/知识和日志边界不变；提示内容不得新增敏感 payload。
- toast 计时器在 provider 卸载和手动关闭时清理，不得形成无界节点或在页面切换后重复。
- 关闭按钮有本地化可访问名称，队列使用 `role="alert"`/live 语义；减少动态效果不依赖动画。
- Poker 玩家卡仍保留本人、行动/待办、庄家、房主、在线和筹码文字语义及房主管理手势。
- 中英文、light/dark、300px、`focus-visible`、无页面横溢和静态资源完全本地继续成立。
- 不修改 initial、`change-0.md`、其他 feature 历史、部署接口或真实部署配置。

## 6. 最终集成、回归与验收流程

1. 同步实现共享 toast、主/管理员应用接入、Poker 玩家卡/准备页、felt 缓存和手机安全
   空间，并更新核心 E2E 的可访问性、DOM 顺序、计时、颜色与几何断言。
2. 在最终源码运行 `npm run lint`、`npm run typecheck`、`npm run test:platform`、
   `npm run test:poker`、`npm run test:avalon`、`npm run test:realtime`、
   `npm run test:e2e:core` 和 `npm run test:capacity`；核心 E2E 包含生产 build/static 与
   Chromium/WebKit。
3. 运行 `git diff --check`，确认无生成物、敏感配置、无关历史或部署接口变化；汇总
   findings。`relaxed` 只允许独立证明无交付影响的 supplemental 异常保留。
4. 写入 phase result、`change-1.md`、更新后的 effective snapshot 与 completed state，
   再按用户授权提交干净 HEAD。
5. 工作流冻结和提交后，读取 `deploy/README.md` 与最新部署状态，使用受支持入口正式
   发布；部署前确认 clean HEAD、固定卷/唯一备份和无遗留状态，部署后只读核验 Git SHA、
   镜像、running/healthy、外部 `/healthz` 与关键浏览器页面。正式发布证据不倒写为阶段
   产品验收。

不计划修改或专项测试 `deploy/**`；若实际差异触及发布接口，先暂停并修订计划。部署入口
自身的既有状态机门禁由受支持脚本执行，任何远端状态不明先做只读检查，不清理未知资源。

## 8. 风险、技术决策与修订记录

| 风险 | 控制 |
| --- | --- |
| 全宽缓存遮挡中心牌面或手机唯一操作 | 缓存仍只在本人行动时位于 felt 底部安全区；固定右侧动作列、稳定高度和 300px 几何为 core 门禁。 |
| 16 节点网格使中间筹码完全覆盖 | 节点数作为 CSS 变量，首尾锚定、中间等分；浏览器测量相邻中心差、首尾边界和按钮可操作性。 |
| toast 自动计时造成测试不稳或内存泄漏 | 独立 ID/计时器映射、卸载清理、手动关闭清理；E2E 只等待可观察的约 5 秒窗口。 |
| 统一 toast 误移除持续警告或字段错误 | 只迁移现有操作 `notice` 与运行时错误；表单 validation、危险影响说明和确认对话框留在上下文。 |
