# 游戏房间界面统一与德州扑克开手体验：实施路线图

## 1. 范围与执行模式

- 功能编号：`game-room-ui-and-poker-hand-start`
- 合同版本：`3.2`
- 需求文档：[requirements.md](requirements.md)
- 执行模式：`single`
- 详细程度：`expanded`
- 交付与验证策略：`relaxed`
- 路线图修订：`1`
- 需求指纹：`sha256:ad5cdcf8d67fee30ddbc71f1ac1b381330a8a3a0d9881d978e22e065c8598351`
- 项目基线：`main@2f1901047ee0e23c2038544db7a7508a8d60aeef`
- 创建日期：`2026-07-31`

本功能使用一个阶段完成共享房间顶栏、Avalon 角色构成与移动布局、Poker 手动盲注和
全员确认、私牌临时查看、下注缓存与手机牌桌调整，以及最终集成验收。协议、投影和 Web
必须在同一个候选结果中一起生效；若把服务端协议与客户端拆成可发布阶段，会留下新手牌
进入 `blinds` 后旧客户端无法继续的非安全产品状态。项目没有 SQL 双写、外部 API 迁移、
独立审批或可单独发布子系统，因此不建立额外阶段。

选择 `expanded` 是因为实现会改变公开命令集合、持久化 `PokerState`、盲注资产流水、
开手并发门禁和旧 JSON 快照解释。阶段内先建立服务端权威、幂等、守恒、私牌隔离和恢复
兼容，再开放对应 Web 入口；这一顺序通过三个任务及任务检查点表达，不把语言边界或测试
本身提升为阶段。

`relaxed` 允许先实现再运行目标验证，不要求红灯优先。全部 `core` 验收、安全、隐私、
资产完整性、旧快照兼容、构建和项目硬门禁仍然阻塞；只有独立证据证明不影响交付行为的
`supplemental` 异常可以按连续 `FND-I-*` 编号报告。

规划前工作区只有用户提供且尚未跟踪的本功能 `requirements.md` 与
`workflow-contract.md`。本路线图只接管本功能后续规划/执行文件和明确范围内的源码、
测试及阶段快照，不把其他冻结功能历史归为本次工作。

需求把正式 `home-table` 发布排除在功能验收之外；用户在本次目标中另行明确授权功能
冻结、提交并推送后通过受支持入口正式发布。因此 initial 阶段只记录本地门禁与隔离
iStoreOS 候选验证，正式发布和发布后浏览器验收作为冻结工作流之外的独立运维动作执行，
不得倒写为阶段证据。

## 3. 全局详细设计

### 3.1 Poker 开手状态与引擎转换

1. `PokerState` 加法保存本手的小盲账户、大盲账户、已提交盲注账户和已确认开手账户。
   盲位由冻结玩家与庄家位置一次性确定；筹码＋牌仍在建手时一次性洗牌/发牌，纯筹码
   模式的 `holeCards` 保持为空。
2. `createPokerState()` 返回 `phase: "blinds"`、`actingAccountId: null`、空盲注池和空
   确认集合，不再调用自动盲注。面值、庄家、玩家、牌堆和底牌仍是本手快照。
3. 新引擎转换分别提交固定盲注和确认开手：
   - 只有本手指定盲位可提交自己的固定盲注；短码提交全部剩余栈；
   - 盲位必须先成功提交盲注才能确认，非盲位可并行确认；
   - 确认只改变确认集合，不改牌、栈、池或流水；
   - 每个转换校验 Poker 版本、阶段、参与资格、重复与顺序。
4. 每次成功转换后检查当前仍未弃牌的冻结参与者。全部完成时在同一引擎变更中进入
   `preflop`，把 `currentBet` 设为完整大盲、保留实际短码贡献、按大盲之后顺序选择首个
   非弃牌且非全押行动者；无人可行动时沿用三秒自动推进。
5. `forceFold()` 在 `blinds` 阶段不创建普通下注行动；它移除该玩家的待办，保留已经
   投入的盲注并重新判断继续、单人胜出或自动推进，保证房主移除不会永久悬挂。
6. 正式 `preflop` 之后的下注、加注、撤销、全押、边池、翻牌、判型和结算函数保持现有
   接口与规则；开手盲注不可撤销，也不写入普通 `undoSnapshot`。

### 3.2 命令、事务、流水与外部兼容

- 新增 `poker.blind.post` 与 `poker.hand-start.confirm` 外部命令，沿用命令 ID、连接
  租约、平台期望版本、Poker 期望版本、Zod 和 `processed_commands`。
- `poker.blind.post` 在一个 `PlatformStore.execute()` 事务中执行引擎转换并按实际提交
  金额写一条 `table-to-pot / blind` 流水；后续失败使状态和流水整体回滚。相同命令 ID
  重放原结果，不同重复命令由阶段/集合/版本校验无变化拒绝。
- `room.start` 只创建开手阶段，不再调用 `recordInitialBets()`。系统自动推进和普通
  `poker.action` 在 `blinds` 不可生效。
- 从客户端命令 schema 和分发中移除 `room.pause`、`room.resume` 与 `avalon.void`；
  未识别的旧外部命令确定性返回无状态变化错误。领域的关闭房间、活动成员离开/移除、
  账户安全删除及恢复路径继续可内部作废、退款和清理秘密。
- 旧 `paused` 房间保持既有状态，调度器不得推进；房主仍可通过 `room.close` 原子退款
  并删除。实现不为旧 paused 状态重新开放恢复入口。

### 3.3 持久化归一化、守恒与移除

- 旧 Poker JSON 缺少开手字段时，根据冻结玩家/庄家补稳定盲位，并把旧活动手标记为盲注
  和确认均已完成；保留旧 phase、底牌、池、栈、版本和行动者，不运行新转换。
- 新 `blinds` 状态的集合、盲位、牌和实际贡献完整保存于现有平台 JSON；重启只重置租约、
  连接和易失准备，不重置这些字段。
- 领域不变量验证新集合只引用冻结玩家、盲位不同且合法、金额安全非负、池与玩家贡献
  一致；任何归一化可重复执行并通过现有 SQLite 事务持久化。
- 活动开手移除沿用当前强制弃牌、剩余栈兑换和已投池保留语义；若只剩一人或无人可行动，
  继续走现有 showdown/自动结算路径。关闭房间继续按 handActive 退款总投入并兑换栈。
- 不新增 SQL 表、迁移脚本或运行时依赖；正式降级仍只能依赖受支持部署流程的升级前完整
  SQLite 备份，不能由旧镜像直接解释含新字段的活跃 `blinds` 手。

### 3.4 公开/私有投影与阶段语义

- Poker 公开投影加法提供盲位账户、已下盲、已确认和仍待完成账户；只暴露账户 ID 与完成
  状态，不包含牌面。玩家、房间观众和匿名大屏消费同一公开完成状态。
- `ownHoleCards` 继续仅在本人有效租约、本人属于当前活动手且为筹码＋牌时返回；日志
  redaction、`assertNoPrivateCards()` 和大屏断言保持阻塞。
- 共用阶段格式化器从权威 `room.status`、Poker `phase` 或 Avalon `phase` 生成双语标签；
  `blinds` 明确表示盲注与开局确认，旧 paused 只显示历史暂停状态而不提供恢复操作。
- Avalon 角色构成仅由公开房间配置和人数派生。等待期人数为房主加在线已准备非房主；
  活动/complete 使用冻结参与人数。预设读取该人数的角色多重集合，自定义读取保存集合并
  独立显示人数不匹配；不得读取 `ownKnowledge`、`roleAssignments` 或 revealed roles。

### 3.5 共用已登录房间顶栏

- 在通用 UI 边界建立一个三段式已登录房间顶栏：左侧返回大厅和离房，中间房间名/本地化
  游戏名/权威阶段，右侧可选房主关闭。组件只接收显示文本和回调，不拥有房间权限或命令。
- Poker waiting/player/spectator 与 Avalon room view 都使用该组件；匿名 Poker/Avalon
  display 保持专用只读标题。
- 桌面返回/离开显示图标与文字；移动端保留 44px 级圆形图标按钮、`aria-label`、
  `focus-visible` 和标题省略。关闭始终在右侧独立 danger 区域并沿用现有确认。
- “返回大厅”仅调用本地视图切换；离房/关闭继续通过服务命令。房内大屏链接全部移除，
  大厅 Poker/Avalon 房间卡现有匿名 display 链接保留并由 E2E 验证。
- Avalon 中间房间名区域可选地渲染为按钮，支持点击、Enter、Space、Escape、外部点击
  和权威房间切换关闭角色构成浮层；Poker 中间区域为非交互标题。

### 3.6 Avalon 准备、构成与移动布局

- 准备卡只保留标题、构成摘要、十个圆点和准备/开始操作；移除可见房主自动准备说明和
  `x/5–10`，用完整 `aria-label` 提供当前/最少/最多人数。
- 房主设置卡作为 action panel 中的独立下一张卡，上下排列；非房主只得到准备卡。保存
  权限和准备清空仍由服务端现有规则控制。
- 共享 `AvalonRoleComposition` 视图在准备摘要、房间名浮层和匿名 display “本局参赛”
  上方复用同一派生结果；重复角色按数量展示，少于五人及自定义人数不匹配提供双语状态。
- 已登录浮层使用 portal/受控层级并在离房、房间 ID/版本切换、Escape、外部点击后关闭；
  display 只显示静态卡，不渲染按钮或点点点提示。
- 300px 下 `AvalonMemberRail` 的玩家卡保持两列，压缩头像、文本和徽标；长按、右键和
  键盘菜单数据属性不变，页面宽度不得超过视口。

### 3.7 Poker 玩家卡、开手卡与私牌按住查看

- 玩家卡的“正式行动者或开手待办”使用整卡操作提示背景；已登录参赛者本人叠加独立
  边框。卡内增加“待操作/已确认/本人”等双语或 ARIA 状态，匿名大屏不计算本人边框。
- 当前本人仍有开手待办时在 felt 上方显示高层级开手卡。盲位先看到固定盲注按钮；成功
  后同一卡显示线上两张牌或实体牌确认。非盲位直接进入确认。按钮发送新权威命令并使用
  当前 Poker 版本。
- 牌桌常态删除 `ownHoleCards` 区域。筹码＋牌活动本人且私有投影存在时，在原暂停控制
  位置显示“查看底牌”；按住 pointer/touch 或 Enter/Space 时显示中央私牌层，任意释放、
  取消、移出、blur、hidden、offline、房间/手牌/连接变化都立即遮盖，单击不锁定。
- 开手确认卡、查看层、下注缓存、结算层和 portal 菜单使用明确 z-index 与互斥显示条件；
  任何本机可见状态都不写命令、SQLite 或 WebSocket。

### 3.8 下注缓存、筹码交互与手机牌桌

- 本机缓存只在 `actingAccountId` 为本人且 phase 为正式下注街道时显示为 felt 内半透明
  卡；开手、他人回合、自动推进、showdown、distribution、complete 时隐藏并按既有版本/
  行动/金额依赖清空。
- 缓存卡固定最小高度和最大宽度，左侧为无可见标题的筹码轨道，右侧为总额与清空。轨道
  用实际“不同面值”数量的有界 DOM 与 CSS 等距网格：首尾贴合容器，中间在空间不足时
  自动均匀重叠；相同面值仍为一枚筹码加 `×数量`。
- 删除 `draggable`、`onDrag*`、指针拖入/拖回状态和拖动点击抑制。筹码架与缓存筹码都是
  button，点击/轻触/键盘分别加一枚/减一枚；筹码架设置水平滚动和 `touch-action: pan-x`。
- 手机座位横向滚动容器增加上下安全内边距，保证阴影、焦点和庄家标识位于裁剪盒内；
  公共牌使用有界 `clamp()` 尺寸和内部字号，五张牌在 300px 中完整显示且不占用页面横溢。

### 3.9 安全、可观察性、发布与恢复

- 客户端完成计数、颜色、动画和悬浮层从不决定阶段；全部写操作依赖服务端租约、版本、
  参与资格和事务。
- 日志只记录命令类型、版本和非敏感拒绝码；新增盲注命令不得记录牌、deck、连接 ID 或
  Avalon 角色归属。
- 不修改 `deploy/**`、Compose、Dockerfile、固定卷或生产健康接口；构建后静态资源继续
  完全本地。
- 本阶段本地门禁通过后，可通过现有 SSH 边界在 `192.168.100.1` 使用随机容器、镜像、
  端口和卷验证 `linux/amd64`、非 root、health、旧 JSON、开手状态及重启恢复。前后只读
  对比正式 `home-table`、固定卷和发布标记；隔离测试不得调用正式部署入口。
- 任一远端归属或清理不确定都暂停并保留诊断，不删除未知资源。正式发布必须等 initial
  冻结、Git 提交和推送完成，再按 `deploy/README.md` 的受支持入口独立执行。

## 5. 跨阶段依赖与不变量

虽然路线图只有一个阶段，任务和任意中断检查点都必须满足：

1. 新开手 UI 在盲注/确认的服务授权、版本、幂等、流水和恢复测试通过前不可成为完成项。
2. `blinds` 阶段不设置普通行动者，不接受 `poker.action`，也不创建撤销快照；实际盲注
   与流水始终一一对应。

## 6. 最终集成与整体验证流程

验证只在结果仍有效的最晚位置运行。T1/T2 的目标验证是进入下一任务的安全门禁；T3

   流水、移除、旧状态和私牌投影达到开放 UI 的门禁。
2. T2 完成 Web 与相关测试后运行目标 `npm run lint`、`npm run typecheck`、
   `npm run test:avalon` 和相关 Chromium/WebKit 测试诊断；失败保持 T2 in-progress，
   不提前形成阶段结果。
3. T3 在最终源码状态依次运行：
   - `npm run lint`
   - `npm run typecheck`
   - `npm run test:platform`
   - `npm run test:poker`
   - `npm run test:avalon`
   - `npm run test:realtime`
   - `npm run test:e2e:core`，由该命令执行生产 build 与静态资源无公网引用检查，并覆盖
     Chromium 桌面、WebKit 手机和显式 300px 场景
   - `npm run test:capacity`
4. 本地门禁通过后执行用户授权的隔离 `npm run test:docker-smoke`，通过 SSH 使用
   iStoreOS Docker daemon和随机资源；前后只读证明正式资源未改变。
5. 运行 `git diff --check`，审计实际差异只包含本功能源码、测试、`AGENTS.md` 阶段快照
   和本工作流文件；不得包含生成物、真实配置、部署接口或冻结历史。
6. 汇总全部 FR、AC 与 NFR。所有 core 和硬门禁必须通过；supplemental 异常只有在独立
   证明无交付影响后才能记录为 `FND-I-*`。随后写不可变阶段结果、`change-0.md` 和
   `effective-requirements.md`。

不运行 `npm run test:deploy`，因为计划不修改部署接口。实际差异一旦触及 `deploy/**`、
`.dockerignore`、Compose 或发布参数，必须先暂停修订计划并增加对应验证。

## 8. 风险、技术决策与修订记录

### 8.1 风险与门禁

| 风险 | 控制与门禁 |
| --- | --- |
| 盲注状态成功但流水失败或重复 | 同一 SQLite 命令事务内变更和记账；重复 ID、不同重复、过期、并发与故障注入由 server/platform 阻塞测试覆盖。 |
| 短额大盲导致错误开局跟注或边池 | 引擎只扣实际栈，但进入 preflop 时保留完整 `bigBlind` 的 `currentBet`；poker 规则/边池回归阻塞。 |
| 旧手牌被当成新 blinds 重发/重扣 | 缺字段归一化为协议已完成；旧活动/paused/complete JSON、重启及守恒测试阻塞。 |
| 断线或移除让开手永久悬挂 | 无自动代操作；重连恢复；forceFold 重算剩余待办并进入继续/结算，关闭仍完整退款。 |
| 私牌在 UI 或日志残留 | 服务投影继续租约隔离；本机层覆盖全部安全事件；日志 redaction、realtime 和 display 对照阻塞。 |
| 取消外部作废误伤内部安全退款 | 只移除 parser/dispatch/UI 入口；领域关闭/离开/移除路径保留并有 Avalon/Poker 资产测试。 |
| 角色构成泄露具体归属 | 纯函数只消费公开 config 和人数；display/观众投影与源码依赖检查阻塞。 |
| 多悬浮层遮挡唯一操作 | 互斥条件、层级表、300px Chromium/WebKit 几何和键盘路径阻塞。 |
| 筹码重叠裁剪端点或手势误下注 | 有界 grid 保留首尾，删除全部拖动监听；16 面值、长数字、触摸横滚和页面宽度测试阻塞。 |
| 远端测试误触正式资源 | 随机资源、前后只读审计、禁止 deploy 入口和固定卷/备份；归属不明立即暂停。 |

### 8.2 技术决策

| 决策 | 结论 | 依据 |
| --- | --- | --- |
| 路线图形态 | `single` | 协议与 UI 必须同候选交付；不存在安全的半协议正式状态或外部迁移边界。 |
| 计划细节 | `expanded` | 持久 Poker 状态、公开命令、盲注流水、旧快照和降级恢复属于合同列明的兼容/数据高风险。 |
| 开手阶段 | 复用真实 `blinds`，以两组账户集合表达盲注和确认 | 保持既有 `HandPhase`，同时无歧义支持公开待办、并发和恢复。 |
| 盲注记账 | 每个成功 `poker.blind.post` 命令写一条实际金额流水 | 使状态、池和 ledger 一一对应，并由现有事务/重放保证原子幂等。 |
| 旧状态 | 缺新字段即视为开手协议已完成 | 当前历史版本从未持久停留在待办 blinds；这是唯一不重发、不重扣、不阻塞的兼容解释。 |
| 外部旧命令 | 从 schema/dispatch 移除并确定性拒绝，内部安全方法保留 | 满足产品入口取消且不破坏关闭、移除和退款。 |
| Avalon 构成 | Web 纯派生公开 config + 选中/冻结人数 | 不新增秘密投影或复制角色分配。 |
| 缓存重叠 | 不同面值一节点、CSS 等距 grid 保留首尾 | DOM 有界、无需测量循环，适配 16 面值和动态宽度。 |
| 远端验证 | iStoreOS 隔离 Docker smoke；正式发布在冻结/提交/推送后另行执行 | 保持功能证据与独立运维授权边界。 |
