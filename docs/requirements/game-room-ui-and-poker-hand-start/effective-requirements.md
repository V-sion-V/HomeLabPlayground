## 1. 当前目标与范围

当前产品在可信家庭 LAN 内为 Poker 与 Avalon 的已登录房间提供一致的顶栏、阶段和
移动布局；公开角色构成与具体角色归属严格分离。Poker 的两种模式都使用服务端权威的
手动盲注和全员开手确认，线上私牌默认遮盖，下注草稿只在本人正式回合短暂出现；瞬时
操作反馈统一从左上角 toast 出现，不再占据页面布局。

当前范围包括共享房间顶栏、大厅匿名 display 入口、Avalon 准备/设置/公开角色构成、
Poker 玩家状态和紧凑卡片、开手协议、私牌按住查看、全宽动态无拖动筹码缓存、300px
牌桌、跨普通/游戏/管理员页面的 transient toast，以及所需契约、领域、命令、投影、
JSON 快照兼容和测试。

当前范围不新增游戏、角色、扑克变体、认证、远程资源、运行时依赖或 SQL 业务表；不改变
Poker 正式下注街道和 Avalon 游戏规则；不修改部署自动化。正式部署是独立运维动作，
不属于本功能的产品验收证据。

## 3. 当前流程

### 3.1 共用房间与公共大屏

1. 已登录成员进入 Poker 或 Avalon 房间，使用同一顶栏返回大厅、合法离房或由房主
   确认关闭。
2. 中间区域持续显示房间、游戏和权威阶段；Avalon 房名可打开公开角色构成浮层，
   Poker 房名为非交互标题。
3. 房间内没有 display、暂停、恢复或手动作废入口。
4. 返回大厅后，房间卡仍可匿名打开不占成员名额的只读 display。

### 3.2 Avalon 准备与角色构成

1. 所有成员看到准备卡；非房主准备/取消，房主按既有资格开始。
2. 十个圆点和构成摘要随房主加在线 ready 成员更新；不足五人或自定义人数不匹配时
   立即说明。
3. 房主在下一张独立设置卡保存配置；既有准备清空和服务端校验语义不变。
4. 房间名浮层与匿名 display 构成卡使用同一公开派生结果。
5. 开局后构成冻结为本局配置和参与人数，具体账户角色继续保密。

### 3.3 Poker 开手

1. 房主从等待或完整结算开始一手，服务端冻结参与者、位置、面值、庄家和盲位；
   筹码＋牌同时洗牌发牌但不扣盲。
2. 非盲确认本人线上牌或实体牌；大小盲先提交固定盲注，再完成相同确认。
3. 每个客户端可独立提交，公开玩家卡只显示待办/完成，不显示牌面。
4. 所有仍有效参与者完成后，服务端进入 `preflop` 并设置行动者。
5. 断线保持等待；重连恢复，或由房主移除/关闭按权威资产语义收口。

### 3.4 Poker 正式行动与私牌

1. 当前行动者整卡使用操作提示背景及统一可读前景，本人卡保留独立边框；在线状态位于
   头像右侧昵称下方。
2. 本人回合可通过点击、触控或键盘把筹码加入贯穿 felt 安全宽度的缓存；当前不同面值
   节点数动态决定等分间距，横向手势只滚动筹码架。
3. 缓存仍通过既有跟注、加注、全押和确认操作提交权威命令。
4. 需要查看线上牌时按住底部按钮；松开或发生任何安全事件立即遮盖。
5. 共享牌桌常态只显示公开牌面和底池。

### 3.5 瞬时操作反馈

1. 普通页面、Poker/Avalon 房间和管理员页面把成功、拒绝、连接关闭或接管等瞬时反馈
   推入同一个左上角 toast 队列。
2. 新提示位于最上方，旧提示向下移动；每条可用本地化关闭按钮立即移除，也会在约五秒
   后独立自动移除。
3. toast 不参与主布局。字段校验、持续风险说明和危险确认仍位于产生决定的上下文中。

## 4. 当前数据、接口与状态

- `PokerState` 持久保存 `smallBlindAccountId`、`bigBlindAccountId`、
  `blindPostedAccountIds` 和 `handStartConfirmedAccountIds`；`phase: "blinds"`
  是真实业务阶段，正式开局前 `actingAccountId` 为 `null`。
- `poker.blind.post` 与 `poker.hand-start.confirm` 使用现有命令 ID、控制租约、平台/
  Poker 期望版本、Zod、SQLite 事务和 `processed_commands` 幂等结果。
- 每个成功盲注按实际金额写一条 `table-to-pot / blind` 流水；确认不写资产流水。
  进入 preflop 时 `currentBet` 使用完整大盲，实际短码贡献保持不变。
- Poker 公开投影提供盲位、已下盲、已确认和待完成账户 ID，不提供牌面；私有
  `ownHoleCards` 继续只进入本人有效控制租约。
- 筹码＋牌可在 `blinds` 保存已发底牌；纯筹码模式的 `holeCards` 始终为空。
- Avalon 构成只从公开配置和准备期选中人数或活动冻结人数派生，不新增角色归属投影。
- 下注缓存、toast 队列/计时器、构成浮层开关和私牌按住状态只存在于本机 React 状态，
  不写命令、WebSocket 或 SQLite。
- `room.pause`、`room.resume` 与 `avalon.void` 不在当前外部 schema/dispatch；
  `room.close`、内部作废及移除/账户删除安全路径继续使用领域能力。
- 没有新增 SQL 表或运行时依赖；新状态仍由现有版本化平台 JSON 快照持久化。

## 5. 当前异常、边界、安全与恢复

- 非指定盲位、重复盲注/确认、确认顺序错误、过期版本、失效租约、跨房或正式下注阶段
  错误命令均无状态变化拒绝。
- 盲注状态与流水全成或全败；命令重放返回既有结果，不会二次扣款。
- 大小盲任意顺序，非盲可并行确认；`blinds` 期间普通 `poker.action` 不生效，也不
  创建普通下注撤销快照。
- 短码盲位投入全部剩余栈；正式翻牌前仍使用完整大盲开局额并跳过全押者，既有边池与
  守恒规则不变。
- 开手断线不自动操作；刷新、重连、接管和重启恢复相同牌、盲注、确认及待办。
- 开手期移除玩家会强制弃牌、已投入留池、剩余兑换，并安全继续、结算或关闭；普通
  离房不能绕过活动手语义。
- 关闭、房主无继任退出、活动 Avalon 成员离开/移除和账户删除仍可内部安全作废、退款
  并清理秘密；这不是手动作废入口。
- 缺少新字段的旧活动 Poker 手视为协议已完成，保留既有 phase、牌、池、栈、版本和
  行动者。旧 paused 快照不推进，可由房主安全关闭。
- 私牌查看层和构成浮层在权威房间/连接变化及所有指定本机安全事件后关闭；秘密不会
  残留到另一账户、连接或房间。
- 自定义 Avalon 角色数不匹配会公开提示，服务端仍无状态变化拒绝非法开局。
- 最多 16 种面值、长数字和 300px 下筹码端点、总额与清空可达，页面无横向溢出。
- 全宽缓存出现时透明空白不拦截牌桌事件，旁观者管理条位于缓存区域之外；多个 toast
  各自清理计时器，空消息不入队，不形成无界持久 DOM。
- 固定顶栏、开手卡、私牌层、缓存、结算层和 portal 菜单使用互斥条件与明确层级，
  小视口使用受控滚动。
- 正式降级只能依赖受支持部署流程的升级前完整 SQLite 备份；不得让旧镜像解释新的
  活动 `blinds` 状态，也不得删除固定卷或唯一备份。

## 8. 当前决策

- initial 使用 `relaxed`；core、隐私、资产、兼容、构建/运行和项目硬门禁全部阻塞。
- 路线图为 `single + expanded`：协议与 UI 同候选交付，展开控制持久状态、命令、流水
  和恢复风险。
- 两种 Poker 模式都手动下盲并全员确认；筹码＋牌显示本人线上牌，纯筹码确认实体牌。
- 大小盲固定金额、短码全押、不可撤销、可任意顺序；非盲可并行确认。
- 开手无自动超时；断线等待、重连恢复，房主用既有移除/关闭解除阻塞。
- 外部暂停、恢复和手动作废退役；内部安全作废继续存在。
- Avalon 准备构成按房主加在线 ready 成员派生，活动/结算按冻结人数；display 持续
  显示公开构成，具体角色归属始终保密。
- Poker 行动/待办使用操作提示背景，本人使用独立边框；公开端无本人语义。
- change-1 使用 `relaxed`，但全部 core 和完整发布前门禁通过，没有保留 report-only
  finding。
- Poker 准备面板无外圈边框，玩家卡采用头像右侧身份块；缓存贯穿 felt 并按当前不同
  面值节点数动态等分，面值/数量行保持紧凑。
- 瞬时操作反馈使用左上角最新在上的五秒 toast；字段错误、持续警告和确认不迁移。
- 新状态使用兼容 JSON 归一化，不新增业务 SQL 表；旧活动手视为开手步骤已完成。
- 正式发布不属于本功能验收；执行时必须使用受支持入口并获得独立授权。

## 9. 已替换或退役项目

- “建手即自动扣除大小盲并直接进入 preflop”已由持久 `blinds`、指定盲位提交和全员
  确认替换。
- “牌桌常态显示本人线上底牌”已由默认遮盖和按住临时查看替换。
- “底部常驻下注缓存与筹码拖动”已由本人回合 felt 缓存和点击/触控/键盘交互替换。
- “固定宽度、固定负间距的 felt 缓存”已由全宽且按当前面值节点数动态等分的缓存替换。
- “页面布局内的单一 notice 字符串”已由可并存、可关闭、自动消失的左上角 toast 替换；
  上下文字段错误和确认对话框不受影响。
- Poker/Avalon 各自不同的已登录房间顶栏已由共享三段式顶栏替换。
- 房间内公共大屏入口已退役；大厅房间卡的匿名 display 入口继续生效。
- 面向用户的 `room.pause`、`room.resume` 和 `avalon.void` 已退役；内部安全路径不受
  影响。
- Avalon 可见房主自动准备说明、`x/5–10` 人数文本、准备/设置宽屏并排和 300px
  单列成员已由紧凑准备卡、辅助技术人数语义、纵向设置卡和双列成员替换。

这些替换不恢复旧行为；后续产品变化必须通过连续 `change-N` 记录。
