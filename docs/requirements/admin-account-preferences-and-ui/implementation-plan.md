# 管理员设置、账户偏好与界面容器统一：实施路线图

## 1. 范围与执行模式

- 功能编号：`admin-account-preferences-and-ui`
- 合同版本：`3.2`
- 需求文档：[requirements.md](requirements.md)
- 执行模式：`single`
- 详细程度：`expanded`
- 交付与验证策略：`relaxed`
- 路线图修订：`1`
- 需求指纹：`sha256:2ea7aa29ee9e4149758016c1f72464f00420f4b639fbb5568a1fb566c01f22d4`
- 项目基线：`main@b131a4c35ec952180beed575e274b9cb27cbccd8`
- 创建日期：`2026-07-30`

本功能使用一个阶段完成共享契约、旧快照归一化、匿名管理员边界、账户/赛季集合操作、
两步登录与账户偏好、管理员和玩家界面、共享固定容器、头像菜单以及最终验收。正式发布
仍不属于本 initial；用户本次额外授权的 `192.168.100.1` 验证只使用随机命名的隔离
Docker 资源和临时端口，不切换 `home-table`、固定卷、正式发布目录或唯一备份。

选择单阶段是因为 Web 与服务端随同一容器发布，新增 JSON 字段可由现有加载路径向前补齐，
没有 SQL 双写、外部 API 兼容期或可独立发布的中间产品。拆成多个阶段反而会产生“新 Web
配旧匿名写入边界”或“新账户字段尚未被全部调用方消费”的不安全中间状态。

选择 `expanded` 是因为账户删除可跨开放房间触发强制弃牌、投入留池、退款、房主转让或
房间关闭，并在同一事务中退役资产、匿名化历史和清除租约；同时旧 SQLite JSON 需要补齐
账户偏好和全局默认主题。阶段内以两个任务和显式门禁表达先服务端、后界面的顺序，不把
实现、测试、文档或远端验收机械拆成独立阶段。

`relaxed` 允许实现先于测试，不要求红灯优先。全部 core 验收、数据完整性、隐私、安全、
兼容、恢复、构建、离线运行和项目硬门禁仍阻塞完成。只有独立证据证明不影响交付行为的
supplemental 异常可以按连续 `FND-I-*` 编号保留。

规划前工作区的唯一未跟踪内容是用户提供的本功能 `requirements.md` 与
`workflow-contract.md`。路线图接管本功能后续规划工件，不改写其他已冻结 feature 历史，
也不把用户提供的两份基线文件冒充为实现修改。

## 3. 全局详细设计

### 3.1 契约、偏好和兼容归一化

1. `Account` 增加 `language`、`theme` 和整数 `volume`。账户对象只返回给本人进入、注册和
   资料保存结果；账户管理摘要、其他玩家房间投影和公共大屏不包含偏好。
2. `GlobalSettings` 增加 `defaultTheme`。新安装保持 `defaultLanguage: "zh-CN"`，
   `defaultTheme: "dark"`；管理员保存把通用项和扑克项作为一个对象交给同一领域校验。
3. 构造旧快照时先补全全局主题，再为缺字段账户补升级后全局语言/主题和音量 100，并把
   `updatedAt` 更新为恢复时刻。已有合法偏好不变；非法或范围外持久值按恢复边界拒绝或
   归一为安全默认的策略必须由测试固定，不允许静默保留 `NaN`。
4. 新增只含账户/赛季摘要、设置和平台版本的匿名管理投影。它不包含租约、房间私有投影、
   流水、隐藏牌、退役内部映射或其他账户偏好。
5. 共享 Zod/TypeScript 类型固定语言、主题、音量、命令 ID、期望版本和去重 ID 集合；
   Web 不复制服务端允许值或资产处理结果。

### 3.2 登录、注册和账户资料边界

- 只读用户名查询接受原始用户名，复用 NFKC、trim 和不区分大小写规则，返回规范化显示值
  与 `exists`，不创建账户、不取得租约、不返回账户资料。
- existing-only 进入只按用户名查找已有账户；不存在返回稳定错误，不接受头像或偏好，
  因而不能在取得租约时顺带修改账户。
- create-only 注册在事务内重新校验唯一性，原子创建账户、当前赛季资产、头像、语言、
  主题、音量 100 和控制租约；检查后竞态返回 `USERNAME_TAKEN`，不降级为进入。
- `account.profile` 扩展为用户名、头像、语言、主题、音量的一次保存。Zod 与领域同时校验，
  任一非法项使快照和当前会话结果全部不变；成功返回完整本人账户。
- 最近账户只帮助重新提交 existing-only 进入；恢复成功后立即采用服务器偏好，已删除或
  失效引用被清理。旧 `party-language`/`party-theme` 不再决定已登录账户。

### 3.3 匿名管理接口和命令事务

建立专用管理读取和写入路由；普通 `/api/command` 不再接受全局设置、账户/赛季删除或
新赛季命令。匿名管理命令不伪造账户 ID 或租约，但必须满足：

1. 由独立 Zod schema 解析，命令 ID、`aggregateId: "platform"`、期望平台版本和 payload
   均受限；无效或空选择在进入 `PlatformStore.execute()` 前拒绝。
2. 设置保存、账户集合删除、历史赛季集合删除和新赛季各自是一个命令；重复 command ID
   重放原结果，过期版本或并发变化返回稳定拒绝。
3. 成功增加平台版本并广播普通大厅、受影响房间和 display 的最新合法投影；删除目标租约
   后现有 subscriber 只收到会话失效或公开状态，不收到管理内部结果。
4. 日志只记录命令类型、非敏感计数、版本和拒绝码；不得记录连接令牌、隐藏牌、原用户名
   映射、完整请求体或资产流水。

### 3.4 账户集合删除和房间处理

账户集合删除在同一个 `PlatformStore.execute()` handler 内采用以下顺序：

1. 去重并冻结目标 ID 集合；在任何房间或资产修改前确认每个目标仍存在，空集合、未知
   目标、过期版本或并发改变直接拒绝。
2. 按稳定房间 ID 遍历含目标成员的房间。若房主未选中，逐个强制移除所选普通成员；活动
   手牌参与者先调用扑克 `forceFold()`，已下注留池，剩余栈兑换，座位和准备移除。
3. 若房主被选中，只从同房间未选中且在线的成员中随机选一次候选。没有候选时调用现有
   `closeRoom()` 作废活动手、退款/兑换并关闭；有候选时先移除其他所选成员，再强制处理
   房主并明确转让给候选。
4. 所有目标离开房间后，领域集合删除按稳定 ID 顺序执行资产退役、历史匿名化、租约清理、
   当前资产和账户删除。全选全部账户会先关闭所有房间，允许当前账户集合为空。
5. 领域不变量、持久化异常或任一步失败由 SQLite 事务回滚完整批次。重复命令只重放原
   结果；新命令对已删目标拒绝，不能重复退款、退役或匿名化。

房间编排位于服务命令与 `PlatformDomain`/扑克引擎的现有组合边界；集合目标校验、账户
退役和赛季清理仍由领域拥有。不得让 Web 提供房主候选、退款额或执行顺序。

### 3.5 赛季集合操作

- 管理投影显示 current 与历史摘要。current 复选框禁用只是界面提示；领域始终再次拒绝。
- 历史删除先校验全部目标属于现存 historical 且没有开放房间，再一次清理所选 Season、
  历史榜单、手牌结果、流水和只被这些赛季引用的匿名辅助项。
- 新赛季只从管理员赛季页发起，继续使用现有无房间、二次确认、归档当前排行榜和按基础分
  初始化账户资产的原子语义。玩家大厅不再发送这些命令。

### 3.6 Web 路由、状态和偏好应用

1. 顶层仅识别 `/admin`、`/admin/accounts`、`/admin/seasons` 为管理员分支；管理员分支
   不启动最近账户恢复、玩家 WebSocket 或玩家状态。History API 维护二级路由和
   `popstate`，生产静态 fallback 支持直达与刷新。
2. 管理员 App 使用 `party-admin-language`、`party-admin-theme` 专用 key，并验证损坏值；
   本地切换立即更新管理员界面，不修改全局草稿。管理员首页宽屏双列、窄屏按通用后扑克
   单列，保存按钮固定于顶栏。
3. 登录首屏只呈现用户名与可读名称的 SVG 右箭头。不存在用户名进入注册页；注册页用户名
   只读、头像按需展开、语言/主题从全局默认初始化，返回不写入。
4. existing-only 或注册成功后，App 同步设置 session、language、theme、volume、lobby
   和房间。`main`/`poker` scope 仍由当前视图决定，mode 始终来自账户。
5. 大厅顶栏只保留头像/用户名账户入口。资料页把头像入口放在用户名右侧，按需展开 32 个
   头像，并在同一提交中保存语言、主题和音量；取消或失败不改变服务器账户。
6. 当前提示音调用接收账户音量，0 时不创建可听输出，非零按比例设置增益；AudioContext
   缺失、自动播放拒绝和播放失败继续被隔离。

### 3.7 图标、固定容器和锚定菜单

- `ui.tsx` 提供可复用 SVG 左/右/下箭头，装饰 SVG `aria-hidden`，按钮本身使用双语名称。
  CollapsibleCard、Select、登录、返回等不再用 Unicode 左/下/右箭头。
- 共享固定框架把外框、header、scroll region 和 footer 分离。所有迁移后的 modal、确认、
  资料和管理员面板使用 `overflow:hidden` 外框、`minmax(0,1fr)` 内容区与
  `scrollbar-gutter: stable`；滚动槽位于边框内且不挤压内容。
- `docs/ui-design-guidelines.md` 记录固定尺寸、窄屏收缩、滚动 ownership、层叠层级、锚定
  浮层、响应式和可访问性规则，后续无需引用本 feature 聊天。
- 头像操作菜单通过 React portal 挂到 body 顶层，以触发按钮 `getBoundingClientRect()`
  定位并夹取到视口；resize、scroll、目标离开或权限变化时更新/关闭。菜单支持首项聚焦、
  Esc、外部点击、Tab 安全退出和触发按钮焦点恢复。
- 菜单只渲染现有房主允许的动作；服务端 `HOST_ONLY`、目标在线、不可移除房主和私牌投影
  仍是最终权威。

### 3.8 发布、隔离环境和恢复

- 本阶段不调用 `deploy/deploy.ps1`，不切换正式服务。候选验证通过本机 Docker 或
  `DOCKER_HOST=ssh://…@192.168.100.1` 向远端 daemon 发送当前工作区构建上下文。
- 远端容器、镜像、卷和端口全部使用本次随机前缀；测试数据只进入随机卷。浏览器技能访问
  临时端口验证管理员直达、登录/注册、偏好和响应式核心流。
- 远端前后只读记录正式容器 ID/镜像/健康、固定卷和已知发布标识；不得读取业务数据。
  成功后只清理能精确证明属于本次随机前缀的资源。归属或清理不确定时暂停并保留现场，
  不删除固定卷、唯一备份或未知恢复状态。
- initial 收口后才能创建最终 Git 提交和推送。正式发布若另行需要，必须从干净已提交
  HEAD 使用受支持入口执行，不能把本次隔离验收描述为发布。

## 5. 跨阶段依赖与不变量

虽然路线图只有一个阶段，任务和任意中断检查点都必须满足：

1. 管理员账户/赛季 UI 在匿名命令的版本、幂等、集合校验、房间事务和投影隔离通过前不可
   到达。
2. 账户偏好只进入本人账户结果；管理员、其他玩家、观众和 display 不得获得其他账户偏好、
   租约、流水、隐藏牌或退役映射。
3. 账户集合删除在任何修改前冻结并验证目标；转让候选只来自未选中在线成员；全部删除允许
   空账户但不能留下房主缺失、部分退出、重复退款或负资产。
4. 当前赛季始终受保护，历史删除仍受开放房间门禁；账户删除不得复用一个会放宽赛季规则的
   客户端或领域分支。
5. 旧 SQLite JSON、既有账户、资产、房间、活动手、排行榜、花色、头像和公共大屏在任何
   检查点可恢复；新增字段不能要求外部迁移服务。
6. 服务端继续是用户名唯一性、偏好、全局设置、房间、资产、删除和权限的唯一权威；客户端
   选择、确认和隐藏按钮不构成校验。
7. 玩家主题 mode 随账户，scope 随视图；管理员本地 mode 与玩家和全局草稿隔离。
8. 隐藏牌隔离、公共大屏匿名只读、控制租约、总量守恒、命令幂等、离线运行和可信 LAN
   警告不得放宽。
9. 不修改冻结工作流、部署自动化、正式服务、固定卷、正式发布目录、唯一备份或真实部署
   配置。

## 6. 最终集成与整体验证流程

验证在其结果仍有效的最晚位置运行。T2 若回改 T1 文件，最终门禁重跑受影响命令；不把
历史结果或模拟结果冒充当前源码证据。

1. T1 完成服务端权威后运行：
   - `npm run typecheck`
   - `npm run test:platform`
   - `npm run test:poker`
   - `npm run test:realtime`
   证明契约、旧快照、注册竞态、偏好保存、匿名管理投影、开放房间批量删除、资产、租约、
   私牌和重启达到开放 UI 的门禁。
2. T2 完成全部源码和测试后，在最终源码状态运行：
   - `npm run verify:core`
   - `npm run test:capacity`
   `verify:core` 内的 E2E 负责最终生产 build 与静态资源无公网引用检查，并覆盖 Chromium
   桌面、WebKit 手机和显式 300px 场景。
3. 在本地门禁通过后，使用 `192.168.100.1` 的随机隔离 Docker 资源运行更新后的
   `npm run test:docker-smoke`，覆盖旧 JSON 偏好补齐、匿名管理集合删除、重启不复现、
   非 root、health 和离线运行。
4. 另起随机临时容器和端口，通过浏览器技能验证 `/admin` 及二级路由直达/刷新/导航、
   注册与账户偏好、固定滚动框、300px 关键操作和头像菜单；前后只读比较正式资源并精确
   清理随机资源。
5. 运行 `git diff --check`，审计实际差异只包含本功能源码、测试、设计文档、项目阶段快照
   和本工作流文件；不得包含生成物、真实配置、冻结历史或部署接口。
6. 汇总 FR/AC/NFR 证据。全部 core 与硬门禁必须通过；`relaxed` 下的 supplemental
   异常只有在独立证据证明无交付影响后才能记录为 `FND-I-*`。之后写不可变阶段结果、
   `change-0.md`、`effective-requirements.md` 和 completed state。

不运行 `npm run test:deploy`，因为计划不修改部署接口。实际 diff 一旦触及 `deploy/**`、
`.dockerignore`、Compose 或正式发布参数，先暂停修订计划。

## 8. 风险、技术决策与修订记录

### 8.1 风险与门禁

| 风险 | 控制和证据 |
| --- | --- |
| 批量中途失败留下部分房间或资产变化 | 进入修改前校验完整集合，所有房间处理和退役处于一次 `PlatformStore.execute()` 事务；持久化故障注入和重放测试阻塞。 |
| 房主转让给稍后删除或离线账户 | 候选只从完整目标集合之外且在线的座位计算；无候选走现有安全关闭；多房间与全选测试。 |
| 强制弃牌错误退款投入或卡住行动 | 复用扑克 `forceFold()` 与 `leaveRoom(..., true)`；活动 actor、非 actor、旁观和 complete 状态分别覆盖。 |
| 旧账户默认值顺序错误或覆盖已有偏好 | 先补全全局默认，再逐账户只补缺失字段；旧 JSON、合法偏好和二次恢复幂等测试。 |
| anonymous admin 误入普通命令或泄漏投影 | 独立路由/schema/dispatch；普通命令拒绝危险类型；序列化断言和日志捕获。 |
| 登录检查与注册竞态覆盖同名账户 | 查询只读；注册事务内 create-only 重查；并发/重复/过期命令测试。 |
| 临时主题预览形成未保存账户状态 | session 只在保存成功后更新；取消/失败恢复服务器账户偏好；测试失败与关闭路径。 |
| 固定滚动容器或 portal 引入焦点/裁剪回归 | 共享原语、稳定 gutter、视口夹取和焦点恢复；Chromium/WebKit、300px 和浏览器现场检查。 |
| 远端隔离资源误触正式服务 | 随机前缀、前后只读指纹、禁止正式名称、精确清理；归属不明立即暂停。 |

### 8.2 技术决策

- 不引入路由、状态管理、UI 或数据库新依赖；使用 History API、React portal、现有 JSON
  snapshot 和 SQLite transaction。
- 不让 `packages/domain` 依赖扑克 UI。活动手 `forceFold()` 继续由服务命令组合层调用，
  领域拥有集合校验、房间/资产不变量、退役和匿名化。
- 空选择由 Web 禁用并由管理 schema 在进入 store 前拒绝，避免成功 no-op 仍增加平台版本。
- 管理员无认证是需求接受的可信 LAN 边界；界面明确危险，但不添加伪权限或隐藏令牌。
