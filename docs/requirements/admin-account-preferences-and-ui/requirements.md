# 管理员设置、账户偏好与界面容器统一：需求

- 功能标识：`admin-account-preferences-and-ui`
- 文档状态：已澄清、可进入独立规划
- schema：`3.2`
- 需求确认日期：`2026-07-30`

## 1. 背景与目标

当前全局设置、账户管理和赛季管理位于已登录大厅的全局设置 modal 中，任何持有有效
账户租约的用户都能进入；语言与亮暗主题又分别存于设备本地。资料编辑直接平铺全部头像，
管理列表以逐项删除按钮和特殊“删除全部”按钮为主，不利于集中选择。不同 modal 还使用
不同滚动容器：全局设置采用固定外框、固定标题/操作和内部滚动，账户资料则让整个 modal
滚动，已经出现滚动条悬空、挤压内容或被放到不相关容器外的问题。

本功能把危险的全局设置与普通玩家大厅分离到只能直接输入地址进入的匿名 `/admin`
管理界面；把语言、亮暗主题和音量变为跟随账户的服务端偏好；重做两步登录/注册、账户资料、
账户/赛季批量选择、箭头图标和固定容器滚动规范，并修复玩家头像操作菜单被相邻座位遮挡的
层级缺陷。

目标用户仍是可信家庭 LAN 中的聚会玩家和维护者。`/admin` 的“管理员”只表示独立的
危险设置界面，不引入管理员身份、密码或权限模型；项目仍不得直接暴露到公网。

## 2. 范围

### 2.1 包含范围

- 新增可直接访问、无需登录且不显示当前用户的 `/admin` 全屏管理员设置路由，并从玩家
  主界面移除全部全局设置入口。
- 管理员首页采用通用设置与游戏卡片的双列布局；通用设置包括默认房主转让秒数、默认语言、
  默认亮暗主题、账户管理入口和赛季管理入口；当前唯一游戏卡片为德州扑克。
- 新增可直接访问并支持浏览器导航的 `/admin/accounts` 与 `/admin/seasons` 二级路由。
- 管理员账户/赛季操作改为复选选择、全选/取消全选、选中数量和列表下方单一危险操作。
- 管理员可删除全部账户。即使存在开放房间，选中账户也先按权威房间退出语义处理，再原子
  退役、匿名化和删除；删除房主时只向未选中且在线的成员转让，否则安全关闭房间。
- 历史赛季仍可选择删除，当前赛季继续受保护；开始新赛季进入管理员赛季管理界面。
- 重做登录/注册：用户名首屏判断已有/新账户；已有账户直接进入；新账户进入独立注册界面。
- 账户资料把头像改为点击当前头像后展开选择，并纳入账户语言、亮暗主题和音量偏好。
- 玩家 `light`/`dark` 主题、语言和音量随账户在服务器持久化；管理员自己的语言与亮暗
  主题仅存当前设备的管理员专用本地设置。
- 大厅右上角只保留一个用户设置入口；语言/主题和全局设置不再作为独立大厅控件。
- 德州扑克设置卡片使用 SVG 左箭头/下箭头表达收起/展开；应用内用作控件的左、下以及本
  功能新增的右箭头统一使用 SVG，不再使用字符箭头。
- 统一所有 modal、弹层和固定面板的外框、固定顶栏/底栏、内部滚动槽和稳定尺寸规则，并在
  `docs/ui-design-guidelines.md` 新建可复用 UI 设计规范。
- 修复等待室、活动牌桌和观众条的玩家头像操作菜单层级、裁剪和视口定位。
- 覆盖简体中文/英文、键盘、鼠标、触控、300px 窄屏、刷新、会话接管、并发和 SQLite 恢复。

### 2.2 不包含范围

- 不新增密码、管理员账户、角色权限、互联网身份或账户所有权证明；原因是产品仍限定在
  可信家庭 LAN，用户明确要求 `/admin` 匿名可用。
- 不提供删除回收站、细粒度撤销或应用内备份恢复；账户退役和历史赛季删除仍是不可逆业务
  操作，只能依靠现有运维整库备份恢复。
- 不允许删除当前赛季，也不改变历史匿名化、排行榜参赛资格、扑克规则、资产兑换比例、
  私牌投影或公共大屏只读边界。
- 不新增主题色板种类。本文中的“主题”“色调”和“界面亮度”均指现有 `light`/`dark`
  模式；`main`/`poker` 仍是由视图自动选择的色板作用域，扑克花色预设仍是独立全局设置。
- 不新增独立音频素材、远程音频服务或公共大屏音量偏好；音量控制现有及后续账户侧产品
  音效。
- 不实现阿瓦隆、狼人杀或其他游戏卡片内容，只保证管理员游戏区域可扩展并展示当前德州
  扑克卡片。
- 不在本需求阶段部署正式服务；实际发布仍需要独立明确授权并使用现有受支持部署入口。

## 3. 已确认的项目事实与约束

- Web 当前没有路由依赖；`App` 只根据查询参数切换匿名公共大屏，Fastify 的生产静态回退
  已能把未知 HTML GET 返回 `index.html`，因此 `/admin` 可在现有 SPA 边界内实现，无需
  引入运行时公网依赖。
- 匿名 `GET /api/state` 当前已经返回大厅、账户管理摘要、赛季和全局设置；所有写命令则
  通过控制租约、期望版本、命令 ID 和 SQLite 事务执行。匿名管理员写入需要新的明确接口
  边界，但不得绕过版本、幂等、校验和事务。
- `Account` 当前只持久化用户名和头像。语言存于 `party-language`，亮暗主题存于
  `party-theme`；扑克阶段变化会无条件尝试短提示音，当前没有产品内音量状态。
- 全局设置当前包含默认语言、默认房主转让时限和扑克默认值，尚无默认亮暗主题。设置更新
  不改变已经创建房间的房主时限；扑克面值仍遵守当前手快照和完整结算后采用新全局值的
  既有语义。
- 当前账户批量删除保护发起账户，且任何开放房间都阻止全部账户/赛季删除；当前赛季不可
  删除。新需求仅替换账户删除的发起者保护和开放房间门禁，不解除当前赛季保护，也不解除
  历史赛季删除的开放房间门禁。
- 强制移除普通成员已有权威语义：活动手参赛者先强制弃牌，已投入筹码留池，剩余筹码退回
  账户，随后移除座位和准备。房主退出已有在线转让或无候选安全关闭语义。
- 账户删除当前会退役剩余资产、清除租约、从活动账户移除身份，并将保留历史替换为稳定、
  不可还原的匿名身份。该守恒和隐私语义必须继续适用于管理员单选、批量和全选删除。
- 当前设置 modal 已有固定外框、固定标题/操作和内部滚动；普通 `.modal` 仍让整个外框
  `overflow:auto`，管理列表又拥有独立滚动，因此需要统一共享容器而不是局部补丁。
- 玩家菜单嵌套在拥有独立层叠上下文的座位元素中。即使菜单自身拥有较高 `z-index`，
  仍可能被后绘制的相邻座位或父容器裁剪，必须修复弹层所有权或父层叠关系。
- 共享契约、领域、持久化、服务、Web 和测试使用 TypeScript ESM workspace；持久化主体是
  SQLite 中的 JSON 快照和命令幂等结果。新增账户/设置字段必须兼容旧快照。
- 服务端仍是账户、房间、赛季、资产和权限边界的唯一权威；客户端选择状态、路由和动画
  不得决定删除、转让、退款、主题持久化或资产结果。
- 新增可见文案必须同时提供简体中文和英文；交互必须支持键盘、触控、`focus-visible`、
  300px 窄屏和无页面级横向溢出。构建产物不得引用运行时公网资源。
- 工作区在澄清开始和需求冻结前均为干净的 `main`；既有功能工作流已经冻结。本功能使用
  独立 schema-v3.2 目录，不改写既有 initial/change 历史。

## 4. 交付与验证策略

- 本次 initial 运行采用用户明确选择的 `relaxed` 策略。
- 实现可以先于测试，但所有 `core` 验收、项目硬门禁、安全、隐私、资产完整性、公共兼容、
  构建、恢复和离线运行要求始终阻塞完成。
- 只有经独立证据证明不影响交付行为的 `supplemental` 异常，才允许记录为带严重程度的
  `FND-I-*` report-only 发现项；不能在失败后把 core 项降级。
- 需求涉及账户数据迁移、匿名无登录写入和开放房间内的不可逆批量删除，后续规划必须为
  这些风险保留原子性、幂等、恢复和并发证据，但不得把纯文档、测试或验证机械拆成独立
  阶段。

## 5. 功能需求

### 5.1 管理员路由与全局设置

**FR-001** `/admin` 必须无需账户或控制租约即可直接加载为全屏“管理员设置”界面。玩家
登录页、大厅、房间、牌桌、观众和公共大屏不得显示或链接该入口；管理员界面不得显示、
恢复或暗示当前账户信息。

**FR-002** 管理员页必须使用固定外框和锁定顶栏。顶栏显示管理员设置标题，右上角依次
提供管理员本地语言、管理员本地 `light`/`dark` 主题和全局设置保存按钮；保存按钮不得
随内容滚动。

**FR-003** 管理员首页在足够宽视口使用左右两列：左列只包含游戏无关的默认房主转让
秒数、默认界面语言、默认 `light`/`dark` 主题、账户管理入口和赛季管理入口；右列展示
所有游戏的设置卡片，当前只有德州扑克。窄屏可按左列后右列的顺序折叠为单列，但不得
隐藏、重排危险含义或产生页面级横向溢出。

**FR-004** 默认房主转让时间必须改为直接输入秒数的数字字段，不再限制为 30/60/120
三个选项。客户端和服务端必须拒绝非正整数及现有房间配置不接受的值；保存只改变后续
新建房间的默认值，不改写既有房间配置。

**FR-005** 管理员全局保存必须原子持久化通用默认值和全部游戏默认值。无效通用字段、
扑克盲注/买入、花色或面值中的任一项必须使整个保存失败且不产生部分状态；已存在的
扑克面值快照、花色投影和完整结算后采用新值的既有语义保持不变。

**FR-006** 德州扑克设置必须作为右列独立可收起卡片。卡片收起时使用 SVG 左箭头，展开
时使用 SVG 下箭头，并保留可读的 `aria-expanded`、键盘、触控和减少动态效果语义。

**FR-007** `/admin` 自身的语言和 `light`/`dark` 只保存在管理员专用设备本地键中，
即时作用于管理员路由，并与玩家账户偏好、玩家登录默认值和全局默认设置相互隔离。
管理员本地切换不得构成全局设置未保存更改。

### 5.2 管理员账户与赛季管理

**FR-008** `/admin/accounts` 与 `/admin/seasons` 必须是可直接访问并支持浏览器
前进/后退的二级管理路由；二级界面提供 SVG 左箭头返回 `/admin`，沿用固定外框、锁定
顶栏/底栏和内部滚动。直接打开二级路由同样无需登录。

**FR-009** 账户列表每项必须提供复选框而不是逐项删除按钮。列表必须提供一个语义完整的
全选复选框：未全选时可选中全部、全选时可取消全部、部分选中时显示不确定状态。列表
下方显示选中数量及“删除选中的用户”危险按钮；空选择时按钮禁用。

**FR-010** 管理员账户页不得保护任何“当前账户”，因为页面没有登录身份。单选、复选和
全选必须允许删除全部活动账户；确认必须列出数量、不可逆性、当前资产退役、活动会话
失效、开放房间处理和保留历史匿名化影响。

**FR-011** 一次账户删除请求必须把选中集合视为同一原子业务操作。每个处于房间中的
非房主目标沿用权威强制移除语义；活动手目标先强制弃牌，已投入筹码留池，剩余筹码退回
账户，再移除座位、准备和当前投影。

**FR-012** 若选中集合包含房主，服务端只可从同房间“未被选中且当前在线”的成员中随机
选择新房主。没有此类候选时，必须沿用现有安全关闭语义：作废未结算手牌、按权威状态
退款、兑换全部成员剩余筹码并关闭房间。全选全部账户时，全部房间必须先在同一事务中
安全关闭，再删除全部账户。

**FR-013** 房间移除、退款/留池、转让/关闭、账户资产退役、历史匿名化、租约失效和活动
账户删除必须全成或全败。任何目标、版本、房间状态、资产不变量、持久化或并发校验失败
都不得留下半退出、无房主、部分匿名化、重复退款、重复退役或负资产。

**FR-014** 被删除账户的所有有效租约必须立即失效。受影响客户端必须安全回到登录流程；
未删除成员必须收到转让、成员移除或房间关闭后的权威投影。公共大屏继续只接收公开状态，
不得因管理员删除获得账户、流水、内部匿名映射或隐藏牌。

**FR-015** 账户删除后必须继续遵守现有退役语义：当前身份、分数、排行榜资格和租约被
移除；需要保留的历史使用稳定、不可还原且彼此可区分的匿名身份；原用户名可创建新账户，
但不得重新绑定旧分数、资格、手牌或匿名历史。

**FR-016** 赛季列表必须用复选框选择历史赛季并提供与账户列表一致的全选/取消全选和
“删除选中的赛季”按钮。当前赛季必须展示但保持禁选、不可删除；全选只覆盖历史赛季。

**FR-017** 历史赛季批量删除仍要求没有开放房间，并必须原子删除所选赛季对应的 Season、
历史榜单、手牌结果、资产流水及只属于这些赛季的匿名辅助记录；当前赛季、当前资产和
未选历史不得变化。空选择不得产生写入。

**FR-018** “开始新赛季”必须移入 `/admin/seasons`，保留名称、基础分、不可逆影响说明、
二次确认、无开放房间门禁和原子归档/初始化语义；玩家大厅不再提供开始新赛季入口。

### 5.3 两步登录、注册与账户设置

**FR-019** 登录首屏必须只显示用户名输入框和其右侧的 SVG 右箭头提交按钮。提交时按现有
NFKC、去首尾空格和不区分大小写规则查询用户名，不得仅凭客户端缓存判断账户是否存在。
空值或非法用户名必须在首屏以双语可行动错误拒绝。

**FR-020** 若用户名已经存在，提交必须直接取得该账户的唯一控制租约、进入原房间或大厅，
并在首个可交互账户画面应用服务器保存的语言、`light`/`dark` 和音量；登录首屏不得
修改或覆盖已有账户偏好。现有最近账户自动恢复可继续存在，但必须消费同一服务器偏好，
失效或已删除最近账户必须清理本地引用并回到用户名首屏。

**FR-021** 若用户名不存在，提交必须进入新账户注册界面。该界面显示不可编辑的规范化后
显示用户名、当前头像入口、语言和 `light`/`dark` 选择；点击当前头像后才展开共享配置
中的全部可选头像，不得在页面初始状态平铺头像。左上角使用 SVG 左箭头返回用户名首屏，
右下角提供“注册并进入”主要按钮。

**FR-022** 新账户注册必须使用 create-only 服务端语义。若用户名检查后发生并发同名创建，
注册必须以明确错误拒绝并保留安全表单状态，不得把请求降级为进入或修改刚创建的同名
账户。成功注册使用所选头像、语言和 `light`/`dark`，音量初始化为 `100`。

**FR-023** 新注册界面的语言和主题初值来自全局默认语言与默认 `light`/`dark`；用户在
注册界面改变它们必须即时更新注册界面并随账户创建原子保存。全局默认值不得覆盖已有
账户偏好。

**FR-024** 大厅右上角必须只保留一个显示头像和用户名的用户设置入口；现有独立语言、
亮暗主题和全局设置按钮必须移除。账户/赛季管理和新赛季也不得从玩家资料或大厅进入。
房间、牌桌、观众和公共大屏继续不显示语言、主题或管理员入口。

**FR-025** 账户设置必须把用户名输入与当前头像入口放在同一主要资料区域，头像位于
用户名右侧；点击头像后展开头像选择界面。选择器关闭或收起时不得平铺头像。旧配置失效
头像继续使用现有安全回退并要求选择合法新头像后才能保存。

**FR-026** 账户设置必须同时提供语言、`light`/`dark` 和 `0–100` 整数音量滑动条。
`0` 表示静音，`100` 表示当前完整音量基准；键盘、触控和辅助技术必须能够读取、改变并
确认当前数值。

**FR-027** 用户名、头像、语言、`light`/`dark` 和音量必须通过一个明确保存动作原子
提交。保存成功后当前客户端立即应用新偏好并更新最近账户缓存；保存失败时服务器和当前
会话不得出现部分资料/偏好，界面保留可修正输入。

**FR-028** 账户语言、`light`/`dark` 和音量必须写入服务器权威账户数据，随该账户跨设备、
刷新、连接接管和服务重启恢复。玩家侧不得再以 `party-language` 或 `party-theme`
作为账户偏好的长期权威；管理员专用本地偏好不受此要求影响。

**FR-029** 账户主题仍使用视图对应的语义色板作用域：登录/大厅/账户设置使用 `main`，
房间/牌桌/观众使用 `poker`。账户只保存 `light` 或 `dark`，不得保存或手工切换
`main`/`poker` scope；扑克花色预设继续正交。

**FR-030** 账户音量必须作用于当前及后续账户侧产品音效。音量为 `0` 时不得产生可听输出；
浏览器自动播放限制、音频 API 缺失或播放失败仍不得阻塞牌局、命令、恢复或界面交互。

### 5.4 图标、滚动容器与头像菜单

**FR-031** 德州扑克展开/收起、下拉框、返回导航以及其他用作控件状态或导航的左/下箭头
必须使用可复用 SVG 图标，不得继续使用 Unicode 字符箭头。新登录提交右箭头同样使用
SVG。装饰图标必须对辅助技术隐藏；有交互含义的按钮必须通过本地化文本提供可读名称，
不得只依赖图形方向。

**FR-032** 所有 modal、弹层和固定管理面板必须采用同一容器结构：外框尺寸在内容增长和
滚动条出现/消失时保持稳定；标题顶栏和底部操作区锁定；只有中间内容区滚动；滚动槽位于
外框边框以内、实际内容盒之外，不得悬空到窗口外、覆盖无关区域或挤压内容宽度。

**FR-033** 固定容器在桌面使用明确最大尺寸，在窄视口按可用宽高收缩；滚动内容、下拉
选项、头像选择和确认弹层不得造成页面级横向滚动。打开/关闭滚动内容前后，同一断点下
非滚动内容的宽度和主要操作位置不得发生由滚动条引起的跳变。

**FR-034** 必须在 `docs/ui-design-guidelines.md` 新建 UI 设计专用文档，持久记录
FR-032–FR-033 的固定外框、固定顶/底栏、稳定滚动槽、层叠弹层、响应式和可访问性规则，
供后续界面复用；不得把该规则写入 `AGENTS.md`。

**FR-035** 等待室、活动牌桌和观众条中由玩家头像打开的踢出/转让菜单必须显示在所有
玩家座位、牌桌内容和普通页面元素之上，不得被相邻玩家、父容器 `overflow` 或自身祖先
层叠上下文遮挡。菜单必须保持在可见视口内，并在空间不足时安全换向或约束尺寸。

**FR-036** 玩家头像菜单必须继续只向有权房主提供合法操作，保留服务端 `HOST_ONLY`、
目标成员和在线转让校验；视觉层级修复不得扩大按钮权限、改变私牌投影或允许移除房主。
菜单必须支持鼠标、触控、键盘、Esc 关闭、外部点击关闭和合理焦点恢复。

## 6. 用户流程或调用流程

### 6.1 已有账户进入

1. 没有可恢复最近账户时，用户看到仅含用户名和 SVG 右箭头的登录首屏。
2. 服务端规范化并查询用户名。
3. 已存在时，服务端取得新控制租约并使旧租约失效。
4. 客户端接收账户资料、语言、亮暗主题和音量，立即应用正确 `main` 或 `poker` scope。
5. 有原房间则恢复原角色与权威投影，否则进入大厅。

### 6.2 新账户注册

1. 用户名查询确认不存在后进入注册界面。
2. 用户名只读；用户点击当前头像展开选择，并调整语言和亮暗主题。
3. 用户可返回首屏，返回不得创建账户。
4. 点击右下角注册按钮后，服务端按 create-only 语义重新检查唯一性并原子创建账户、
   初始赛季资产、偏好和控制租约。
5. 并发同名时拒绝并显示可行动错误；成功时进入大厅。

### 6.3 账户设置

1. 已登录用户从大厅右上角唯一用户入口打开账户设置。
2. 用户编辑用户名，点击右侧头像展开选择，并设置语言、亮暗主题和音量。
3. 保存时一次提交全部资料和偏好；服务端原子校验用户名唯一、头像、语言、主题和音量。
4. 成功后当前 UI 和声音立即采用新值，后续设备登录、刷新和重启继续读取服务器偏好。

### 6.4 管理员设置

1. 维护者直接输入 `/admin`；页面不要求账户，也不显示玩家身份。
2. 管理员本地语言/主题立即生效但不属于全局待保存状态。
3. 左列编辑通用默认项或进入账户/赛季管理；右列展开德州扑克卡片编辑游戏默认项。
4. 顶部保存一次提交完整全局设置；成功或失败均以管理员本地语言显示明确状态。

### 6.5 账户批量删除

1. 管理员在 `/admin/accounts` 单选、多选或全选账户。
2. 下方操作显示选中数量；确认说明房间、资产、会话、历史和不可逆影响。
3. 服务端在一个事务中冻结选中集合和相关房间事实。
4. 非房主目标强制移出；选中房主只向未选中在线成员转让，没有候选则安全关闭房间。
5. 完成退款/留池/转让/关闭后退役资产、匿名化历史、清租约并删除全部目标。
6. 广播更新未删除玩家和公共大屏；失败则所有状态回滚。

### 6.6 赛季管理

1. 管理员进入 `/admin/seasons`，当前赛季显示为禁选保护项。
2. 历史赛季可单选、多选或全选，并在下方一次确认删除。
3. 有开放房间时删除整体拒绝；无房间时原子清理所选历史。
4. 同一界面可发起新赛季，沿用无房间、二次确认和原子归档/初始化。

## 7. 数据、接口与状态

- `Account` 必须新增服务器持久化偏好：`language: "zh-CN" | "en"`、
  `theme: "light" | "dark"` 和 `volume: number`（整数 `0–100`）。这些字段与用户名、
  头像和 `updatedAt` 同属账户资料更新事务。
- `GlobalSettings` 必须新增 `defaultTheme: "light" | "dark"`。`defaultLanguage` 和
  `defaultTheme` 为新注册初值及无账户登录界面的默认显示；不覆盖已有账户。
- 新安装继续使用简体中文作为默认语言；为既有持久状态补齐 `defaultTheme` 时采用
  `dark`，以匹配当前未初始化页面的深色基准。既有账户缺少偏好时使用升级后全局默认
  语言/主题和音量 `100`，并原子持久化安全默认值。
- 管理员本地语言和主题使用与 `party-language`、`party-theme` 及账户数据不同的
  管理员专用 key。账户偏好迁移完成后，普通玩家流程不得把旧设备 key 当作权威。
- 用户名查询必须是只读、规范化且不创建账户；新账户注册必须与“进入已有账户”使用不同
  的服务端意图，防止检查与提交之间的竞态修改同名账户。
- 管理员读取只返回管理所需的账户摘要、赛季摘要、全局设置和必要版本，不返回连接令牌、
  隐藏牌、完整流水或退役身份内部映射。
- 管理员写入虽不要求账户租约，仍必须携带服务端认可的命令 ID/幂等键和期望平台版本，
  并由与普通命令相同的 SQLite 单事务、领域校验和稳定结果语义约束。
- 账户批量删除输入是去重后的账户 ID 集合。服务端必须在事务内重新解析目标、房间、
  选中集合、可转让候选和资产，不能信任客户端提供的房主候选、退款额或执行顺序。
- 删除结果继续报告已删除、受保护、no-op 等稳定事实；管理员全选没有发起者保护。
  当前赛季仍出现在赛季删除 `protectedIds` 中。
- WebSocket/HTTP 广播继续使用公开大厅、本人房间和匿名 display 投影边界；偏好不必进入
  其他玩家或公共大屏投影。
- 路由状态必须与浏览器地址一致。刷新 `/admin`、`/admin/accounts` 或
  `/admin/seasons` 必须恢复对应页面；无关未知路径继续遵守现有静态回退/404 边界。
- 除扩展现有 SQLite JSON 快照外不要求新增数据库引擎或外部存储。若后续设计选择 SQL
  migration，也必须保持相同升级、回退和卷保留结果，不得丢失旧状态。

## 8. 异常、边界与恢复

- `/admin` 匿名写入是用户明确接受的可信 LAN 行为；界面和接口必须清楚标记危险操作，
  但不得伪装成有认证的管理员权限。项目文档继续警告不得公网暴露。
- 管理员全局保存遇到过期版本、并发保存、非法字段或持久化失败时整体拒绝，并重新取得
  最新设置供用户合并；不得静默覆盖较新的管理修改。
- 用户名查询结果只代表查询时刻。注册提交必须重新校验；并发同名以 `USERNAME_TAKEN`
  或等价稳定代码拒绝，不得进入或覆盖现有账户。
- 已有账户进入不接受登录首屏偏好，因此不得通过构造请求在获取租约时顺带修改资料。
  偏好修改只通过取得租约后的账户设置保存。
- 账户批量删除中的任一目标不存在、集合变化、目标房间变化、退款/退役不变量失败、
  版本过期或 SQLite 异常必须回滚完整批次。相同幂等键只重放原结果。
- 活动手选中普通成员时，强制弃牌必须与现有底池/行动继续语义一致；已下注不退回，
  未投入栈和非当前手座位筹码正确兑换。
- 选中房主时不得把房主转让给同一批次稍后将删除的账户。若没有未选中在线候选，即使
  存在未选中离线成员，也安全关闭房间、退款并通知所有成员。
- 全选全部账户后允许活动账户集合为空；当前赛季继续存在，后续新账户按当前赛季基础分
  和全局默认偏好独立创建。空账户状态不得使管理员页、登录页、排行榜或重启失败。
- 历史赛季删除仍被任何开放房间阻止；账户删除不再使用此门禁。两种删除不得共享一个会
  错误放宽赛季安全规则的客户端判断。
- 当前赛季选择框必须禁用且服务端仍拒绝构造的删除请求。选择消失、成功删除或并发更新
  后，客户端必须从最新投影清理已失效选择。
- 音量缺失、`NaN`、非整数或范围外必须拒绝；旧快照只补 `100`。音量 `0` 不创建可听
  输出，音频失败被隔离且不影响状态。
- 管理员本地存储损坏或含非法语言/主题时回退到全局/系统安全显示，不得阻止管理员页面
  加载或修改服务器数据。
- 固定滚动容器内容为空、很短、很长、下拉展开、头像展开、错误提示出现或确认层叠时均
  保持顶栏/底栏可达和内容宽度稳定。
- 玩家头像菜单在靠近视口边缘、300px 视口、滚动容器、结算层和观众条中不得被裁剪；
  菜单关闭后焦点回到触发头像，目标离开或权限变化时菜单安全关闭。
- 旧客户端与新服务端的兼容只保证不会破坏业务数据或绕过服务端校验；正式发布是同一
  容器内 Web/服务端同步更新，不要求长期支持旧 Web 写入新偏好接口。
- 升级失败或新代码无法健康启动时，必须依赖现有部署自动化与 SQLite 整库备份回退；
  不得通过删除命名卷、固定备份或未知恢复状态来“修复”。

## 9. 非功能需求

**NFR-001 数据完整性**：账户房间退出、退款/留池、房主转让/关闭、资产退役、匿名化和
批量删除必须保持总量守恒、非负、无重复、全成或全败。

**NFR-002 隐私与权限边界**：匿名管理员接口不得返回隐藏牌、连接令牌、私有房间投影、
完整资产流水或退役内部映射；公共大屏继续匿名、只读且不占名额。

**NFR-003 响应式布局**：桌面双列管理员布局和 300px 起的窄屏单列布局不得产生页面级
横向溢出；固定容器顶栏、底栏、内容和滚动槽始终可达且不互相挤压。

**NFR-004 可访问性**：全部新路由、复选框、全选不确定状态、滑动条、头像展开、SVG
按钮、listbox、确认和玩家菜单支持可读名称、合理焦点顺序、键盘、触控和
`focus-visible`；危险、禁用和保护状态不只依赖颜色、方向、hover 或动画。

**NFR-005 本地化**：管理员、登录/注册、账户偏好、批量删除、房间强制退出、赛季和错误
文案全部提供简体中文与英文；账户语言切换后当前画面立即一致更新。

**NFR-006 兼容与恢复**：既有账户、赛季、房间、活动手牌、流水、排行榜、花色、头像、
公共大屏和 SQLite 卷可升级；重启恢复服务器账户偏好且不恢复已删除账户、房间成员或旧
租约。

**NFR-007 并发与幂等**：用户名查询/注册、偏好保存、管理员设置、批量删除、房间状态和
广播竞争只产生一个权威结果；重复请求不得重复退款、退役、匿名化、归档或创建账户。

**NFR-008 性能与容量**：约 15 个活动账户、1–2 个房间、32 个头像和合理历史赛季下，
管理员选择、菜单、主题切换、音量更新和广播无明显阻塞、无界节点或持续重绘。

**NFR-009 离线运行**：运行时不得新增公网、CDN、云数据库、第三方身份、远程字体或远程
音频依赖；SVG 与全部资源随构建产物本地提供。

**NFR-010 工程边界**：共享契约、领域、持久化、Fastify、React 和测试保持严格
TypeScript、ESM 与 workspace 边界；不得用客户端隐藏按钮代替服务端删除和偏好校验。

**NFR-011 可观察性**：结构化日志可定位管理员保存、注册竞态、偏好校验、批量删除、
房主转让/关闭、迁移和恢复拒绝，但不得记录隐藏牌、连接令牌、原用户名映射或完整管理员
请求体中的不必要资料。

**NFR-012 设计规范持久化**：`docs/ui-design-guidelines.md` 必须成为固定容器与弹层
规则的项目级设计依据，内容应足以让后续界面无需参考本次聊天即可复用。

## 10. 初步实现方向与影响范围

- 在 Web 应用顶层增加轻量路径解析和管理员页面分支，复用 Fastify 现有 SPA 静态回退；
  不因三个本地路由引入新路由依赖。
- 把管理员首页、账户管理、赛季管理和共享固定框架拆成平台 UI 组件；通过路径导航而不是
  大厅 modal 状态承载二级页面。
- 扩展共享 `Account`、`GlobalSettings`、管理摘要和请求/结果契约；在领域构造恢复时为
  旧 JSON 补齐安全默认偏好。
- 将当前 `/api/enter` 的“查询、已有进入、创建”混合语义拆成只读用户名判断、已有账户
  进入和 create-only 注册；账户资料命令扩展为资料与偏好原子保存。
- 为匿名管理员提供受 Zod、版本、幂等键和 SQLite 事务保护的读取/写入边界；领域层提供
  集合式账户删除和历史赛季删除，不能在 Web 中循环调用单项删除。
- 抽取房间成员强制移除/房主安全退出的领域服务，使普通房主操作和管理员删除复用同一
  资产语义；批量删除先按完整选中集合决定合法房主候选。
- 把账户主题提升为 App 级账户状态，在 main/poker scope 变化时读取服务器偏好；管理员
  另用专用本地 hook。把阶段提示音增益与账户音量关联。
- 建立共享 SVG Icon 组件，替换折叠卡和自定义下拉中的字符箭头，并用于新增登录导航。
- 建立共享固定 Shell/ScrollRegion/Header/Footer 结构或等价 CSS 原语，迁移设置、资料、
  管理和相关确认弹层；用稳定 gutter/轨道结构避免宽度跳变。
- 将成员菜单挂载到不受座位层叠上下文和牌桌裁剪限制的弹层层，或在不扩大权限的前提下
  建立等价的顶层浮层所有权；定位必须锚定触发头像并响应视口边界。
- 主要影响文件预计包括 `packages/contracts`、`packages/domain`、`apps/server`、
  `apps/web`、平台/服务/realtime/E2E 测试和新 UI 设计文档；不需要修改 Dockerfile、
  部署状态机或扑克规则引擎接口，除非规划审计发现复用强制弃牌必须最小调整服务边界。
- 需求涉及共享持久化和开放房间资产迁移，后续路线图应以一个连贯实现阶段为默认，但可因
  领域级批量删除/账户迁移的高恢复风险选择 expanded 细节；不得仅按前后端或测试机械拆分。

## 11. 验收标准

| 验收 | 层级 | 可观察结果 |
| --- | --- | --- |
| AC-001 | core | 直接打开或刷新 `/admin` 无需登录并显示全屏管理员设置；玩家所有界面均无管理员/全局设置入口，管理员页无当前用户信息。 |
| AC-002 | core | 桌面管理员首页为通用设置/游戏卡片双列，窄屏安全单列；顶栏和右上保存固定，管理员语言/主题本地保持且不修改账户或全局待保存值。 |
| AC-003 | core | 默认语言、默认 `light`/`dark`、任意合法正整数房主转让秒数和德州扑克默认值可一次保存、刷新及重启恢复；任一非法字段使整个保存无变化失败。 |
| AC-004 | core | 德州扑克卡片收起显示 SVG 左箭头、展开显示 SVG 下箭头；下拉、返回和登录导航不再使用字符箭头，并保留正确键盘、触控和可读名称。 |
| AC-005 | core | 登录首屏只有用户名和 SVG 右箭头；已有账户直接进入并应用服务器偏好，新用户名进入可返回的注册页，注册页用户名只读且头像点击后才展开。 |
| AC-006 | core | create-only 注册在并发同名时明确拒绝且不修改同名账户；成功注册原子保存头像、语言、主题、音量 100、初始赛季资产和租约。 |
| AC-007 | core | 大厅右上只有一个用户设置入口；资料页可编辑用户名、展开头像、语言、`light`/`dark` 和音量，并通过一次保存全成或全败。 |
| AC-008 | core | 账户语言、主题和音量在同设备刷新、跨设备接管及服务重启后跟随账户；main/poker scope 正确且音量 0 静音、非零按比例播放，音频失败不阻塞游戏。 |
| AC-009 | core | `/admin/accounts` 支持逐项、多项、全选、取消全选和部分选中状态；无发起者保护，可确认后删除最后一个及全部账户，空选择不写入。 |
| AC-010 | core | 删除开放房间中的非房主时强制弃牌、投入留池、剩余兑换、成员/准备移除和牌局继续正确；客户端和公共投影及时更新。 |
| AC-011 | core | 删除房主只转让给未选中在线成员；无候选时安全作废、退款、兑换并关闭。全选全部账户会安全关闭全部房间并在一个事务中删除全部账户。 |
| AC-012 | core | 单选/批量账户删除保持资产守恒、租约失效、历史不可还原匿名化和同名重建隔离；重复、过期、并发或持久化失败不产生部分删除、重复退款或无房主状态。 |
| AC-013 | core | `/admin/seasons` 支持历史赛季复选、全选/取消和选中删除；当前赛季禁选且服务端保护，有房间时整体拒绝，成功时只清理所选历史关联数据。 |
| AC-014 | core | 新赛季只从管理员赛季页发起，沿用无房间、二次确认、历史归档、基础分初始化和原子失败语义；玩家大厅无入口。 |
| AC-015 | core | `/admin/accounts`、`/admin/seasons` 可直达、刷新及前进/后退，SVG 返回 `/admin`；所有管理路由中英文、桌面与 300px 触控/键盘均可完成核心操作。 |
| AC-016 | core | 设置、资料、管理和固定弹层的外框、顶栏、底栏及内容区结构一致；滚动条出现/消失不改变内容宽度，不悬空、不越框、不覆盖无关容器，页面无横向溢出。 |
| AC-017 | core | 等待室、活动牌桌和观众条的头像操作菜单始终位于全部座位和牌桌内容之上且不被裁剪；边缘视口可见，关闭和焦点恢复正确，权限与服务端拒绝不变。 |
| AC-018 | core | 旧 SQLite JSON 自动补全全局默认主题和账户语言/主题/音量，既有账户、资产、房间、手牌、排行榜、花色、头像和公共大屏不损坏；重启不恢复已删身份或旧租约。 |
| AC-019 | core | 匿名管理员投影和日志不暴露隐藏牌、连接令牌、完整流水或退役内部映射；公共大屏继续匿名只读，运行时无公网依赖。 |
| AC-020 | core | 与变更层匹配的 lint、严格类型检查、平台/服务、扑克状态相关、实时投影、核心浏览器、生产构建/静态资源和差异硬门禁通过。 |
| AC-021 | supplemental | Chromium 与 WebKit 中管理员路由、稳定滚动槽、头像展开、range、listbox、复选不确定状态、菜单定位和焦点不存在影响 core 操作的差异。 |
| AC-022 | supplemental | 目标容量和合理账户/历史增长下，批量选择、管理员投影、主题应用、音量和菜单定位保持有界且无明显持续卡顿。 |
| AC-023 | supplemental | 结构化日志足以定位管理员保存、注册竞态、偏好迁移、批量删除和房主处理拒绝，且不含敏感数据。 |
| AC-024 | supplemental | `docs/ui-design-guidelines.md` 的固定容器、滚动槽和弹层规则经独立文档审阅可由后续界面直接采用，无需依赖本需求聊天上下文。 |
