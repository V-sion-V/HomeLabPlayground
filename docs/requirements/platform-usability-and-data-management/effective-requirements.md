## 1. 当前目标与范围

本功能为家庭局域网聚会游戏平台提供游戏无关的参赛排行榜、账户和赛季数据管理，
同时修复德州扑克完整结算至下一手之间的成员生命周期，并统一游戏内控件、移动座位、
声音和错误体验。

当前范围包括：

- 当前及未来赛季的真实参赛资格、单一赛季选择和新赛季空榜；
- 账户逐个/批量删除、自删登出、租约失效、当前资产退役、历史匿名化和同名重建；
- 历史赛季逐个/批量永久删除及关联榜单、手牌、流水清理；
- complete 阶段退出、重新买入、准备和下一手选人；
- 登录/大厅独占语言和主题切换，所有游戏内/观战/公共展示不显示该入口；
- 扑克阶段提示音保留且无产品内静音，移动座位双标签与 300px 顶部布局；
- 旧 SQLite JSON、事务幂等、WebSocket 投影、双语、触控/键盘和离线容器恢复。

不包含管理员/密码/账户所有权证明、删除撤销/回收站、应用内备份恢复、旧历史排行榜
回算、扑克规则变化、新游戏实现、音量入口重做或运行时公网依赖。正式部署仍使用现有
部署自动化，不属于产品需求本身。

账户、赛季、排行榜、设置、数据管理和大厅导航属于平台层；德州扑克专属内容只拥有
牌桌、当前手参与者和牌局生命周期。后续游戏可向同一平台参赛事实边界提供结果，不得
要求大厅或排行榜导入游戏规则。

## 3. 当前流程

### 3.1 两手之间退出与重进

1. 一手完整结算后房间进入 `complete`，座位筹码已与结算结果同步。
2. 玩家确认离开；服务端在最新版本下兑换权威座位筹码，移除座位和准备，并把旧手牌
   玩家标记为已离开。
3. 大厅、成员、观众和大屏立即不再把该账户显示为当前房间成员。
4. 账户可输入新的合法买入重新加入，成为可准备成员；下一手只读取新座位筹码。
5. 已有成员退出后不允许撤销旧结算；活动手普通参赛者继续禁止自行离开。

### 3.2 排行榜与赛季选择

1. 新赛季初始排行榜为空；创建账户、加入或观战不会上榜。
2. 正常未撤销手牌结算后，该结果全部实际参与者进入当前榜单。
3. 单一下拉可选择 current 或倒序历史快照；目标被删或 current 更新时安全回退。

### 3.3 账户管理

1. 已登录账户从大厅设置打开账户管理，查看当前未删除账户、保护项和批量目标数量。
2. 逐个或批量操作必须再次确认匿名化、资产/会话影响和不可撤销性。
3. 服务端确认无开放房间、租约和版本有效后原子执行。
4. 删除他人后其租约失效；删除自己后当前客户端先清本地会话再返回登录。
5. 原用户名可以创建新账户，但不继承旧身份、分数、资格、手牌或匿名历史。

### 3.4 赛季管理

1. current 显示为受保护；历史赛季可逐个或全部选择。
2. 确认明确说明榜单、手牌和流水永久删除且应用内不可恢复。
3. 服务端原子清理关联数据，立即广播新大厅投影；current 和保留数据不变。

## 4. 当前数据、接口与状态

- `PlatformSnapshot.retiredIdentities` 以原账户 ID 作为仅服务端内部键，值只保存随机
  `publicId`、稳定 `anonymousNumber` 和 `retiredAt`；不保存原用户名或头像。
- 历史榜单、手牌参与者、派彩、玩家结果和摊牌身份使用公开匿名 ID 与匿名标记。
  Web 显示“已删除玩家 N”/“Deleted player N”；普通投影不返回内部映射或流水。
- 平台参赛事实只包含结果 ID、游戏类型、赛季 ID、参与者、有效和撤销状态。当前扑克
  `HandResultSummary` 是首个适配器；平台排行榜不读取牌型、底池或下注。
- `Room.seats` 是当前房间成员集合；`PokerState.players` 是当前/已完成手参与者集合。
  `departedAccountIds` 防止旧结果覆盖退出后重进座位，同时保留结算展示历史。
- 删除命令保持现有命令信封：
  `account.delete`、`account.delete-others`、`season.delete`、
  `season.delete-history`，均使用 `aggregateId: "platform"`、命令 ID、期望版本和
  `connectionId`。
- 账户退役流水以 `asset-retirement` 为目的地；当前不变量为“发行量减退役量 =
  活动账户资产 + 桌上筹码/下注/底池”。
- 删除历史赛季同步清理 `seasons`、`historicalSeasons`、匹配 `seasonId` 的
  `handResults` 和 `ledger`，并引用感知清理不再需要的退役身份。
- 持久化继续使用现有单一 SQLite JSON 快照和 `processed_commands`；没有新增 SQL
  schema 或运行时依赖。

## 5. 当前异常、边界、安全与恢复

- 存在任何受管房间时，所有账户和赛季删除均以 `ROOMS_MUST_CLOSE` 无变化拒绝。
- current 赛季删除以 `CURRENT_SEASON_PROTECTED` 拒绝；批量只选择历史赛季。
- 逐个自删允许，批量账户删除永远保护发起者；空批次返回明确 no-op。
- 目标不存在、过期版本、失效租约、重复新命令或持久化异常不得命中新同名对象或产生
  部分删除；相同 command ID 只重放原结果。
- 匿名化或关联清理任何一步失败，SQLite 事务回滚整个命令。
- 旧快照缺字段时只补安全默认值，不主动匿名化现有身份。升级后已经发生删除的数据若
  要降级，必须恢复升级前完整 SQLite 备份，不得直接由旧镜像解释。
- 公共大屏保持匿名、只读、不占成员名额；隐藏牌仍只进入本人有效控制租约投影。
- 产品运行在可信 LAN，但可信 LAN 不放宽授权、隐私、守恒、幂等、并发或持久化。
- 运维整库备份恢复会恢复到备份时的整体状态；产品不提供细粒度删除撤销。
