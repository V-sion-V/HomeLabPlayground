## 1. 阶段目标、边界与关联需求

本阶段先用确定性失败断言锁定两个正式环境缺陷，再修复：

- RC-1-001 / AC-C1-001：complete 阶段退出者从所有当前结算投影立即消失，同时底层
  手牌历史完整保留；

  文字与表面保持可读且不出现游戏内主题入口。

阶段不修改命令、持久化 schema、扑克规则、资产、容量、部署脚本或远端服务。

## 3. 验证与完成条件

1. 领域证据同时证明：
   - 当前房间结算投影不含已离开账户的参与者、派彩、玩家结果和摊牌身份；
   - `PlatformSnapshot.handResults` 仍保留原参与者和结算细节；
   - 同账户重新加入不会重新绑定旧结算身份。
2. Chromium 与 WebKit 真实浏览器证据同时证明：
   - 结算页刷新前后 `data-theme`、`data-theme-scope="poker"`、语义色板和关键计算颜色
     一致且可读；
   - 结算阶段退出后，其他玩家和匿名 display 的结算列表立即移除该玩家；
   - 游戏内仍没有语言或主题切换控件。
3. 计划列出的 lint、类型、平台、实时、生产 E2E、构建/静态资源和差异检查全部通过。
   strict 模式不允许豁免本阶段任何异常。
4. 最终差异只包含 change-1 工作流、最小生产修复和对应测试；不修改冻结 initial、
   `change-0.md`、部署接口、真实配置或生成目录。
