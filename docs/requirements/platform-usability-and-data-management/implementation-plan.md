# 平台易用性与数据管理增强：实施路线图

## 1. 范围与执行模式

- 功能编号：`platform-usability-and-data-management`
- 合同版本：`3.2`
- 需求文档：[requirements.md](requirements.md)
- 执行模式：`single`
- 详细程度：`expanded`
- 交付与验证策略：`relaxed`
- 路线图修订：`1`
- 需求指纹：`sha256:d06b6407f4c128431551c1ff148efe8ef285b2285c291ea1b22e52265c777f4a`
- 项目基线：`main@d55c2568abcb2b67871c58b53559d7b05a32232c`
- 创建日期：`2026-07-29`

本功能使用一个阶段完成平台权威数据、命令、投影、Web 交互、德州扑克两手间生命周期修复和最终验收。所有变化都位于现有 `PlatformSnapshot` JSON、现有命令信封和现有 HTTP/WebSocket 接口内，不需要 SQL 双写、线上数据搬运窗口、外部 API 过渡或独立交付子系统，因此没有足以把路线图拆成多阶段的安全边界。

选择 `expanded` 是因为账户删除、身份匿名化、资产退役和历史赛季删除具有不可逆数据语义；实现还会改变持久化快照、公开历史身份、控制租约和当前赛季守恒计算。阶段内必须先使服务端保护、原子性、兼容恢复和投影隔离成立，再开放平台数据管理 UI。这个顺序由两个任务和任务间门禁表达，不把服务端和 Web 人为拆成可独立发布的阶段。

`relaxed` 允许先实现再运行目标验证，不要求红灯优先。全部 `core` 验收、安全、隐私、数据完整性、旧快照恢复、公共接口兼容、构建和项目硬门禁仍然阻塞；只有独立证据证明不影响交付行为的 `supplemental` 异常可以按连续 `FND-I-*` 编号报告。

规划前工作区只有用户创建且尚未跟踪的本功能 `requirements.md` 与 `workflow-contract.md`。本路线图只接管本功能规划文件，并按用户在 2026-07-29 的明确回答修订需求决策来源及平台/游戏边界；不把其他文件或冻结功能历史归为本次工作。

## 3. 全局详细设计

### 3.1 平台组件和所有权

1. `packages/contracts/src/index.ts` 定义平台级退役身份、历史展示身份、管理摘要、删除命令结果和游戏无关参赛事实契约。扑克 `HandResultSummary` 继续保存扑克结算细节，但只由适配器读取其 `seasonId`、`outcome`、`participantAccountIds` 和 `reversedAt`。
2. `packages/domain/src/index.ts` 负责平台参赛资格、账户/赛季删除、匿名化、资产退役、旧快照归一化、两手间成员协调和所有不变量。平台排行榜不得读取牌型、底池、下注或 Web 牌桌状态。
3. `apps/server/src/app.ts` 负责新命令的 Zod 输入、控制租约、执行时保护、错误码、会话失效和实时广播；确认框显示内容不成为服务端授权依据。
4. `apps/web/src/platform-ui.tsx` 作为新增的平台 UI 边界，承载排行榜赛季选择、账户管理、赛季管理及其确认流程。组件只依赖平台投影与通用 UI，不导入扑克状态或扑克组件。
5. `apps/web/src/main.tsx` 保留应用路由、会话和当前扑克视图组合；登录和大厅拥有语言/主题控件，等待室、牌桌、观战和公共大屏不再渲染这些控件。
6. `apps/web/src/ui.tsx` 继续承载通用 listbox、确认对话框、主题切换和焦点行为；`styles.css` 与 `locales.ts` 提供平台管理和扑克移动展示所需的双语、响应式与状态样式。

不新增第三方运行时依赖，不修改 `packages/poker` 的规则、判型或分池接口，不修改 `deploy/**`、生产 Compose、固定卷或真实部署入口。

### 3.2 持久化身份、公开历史和兼容归一化

- `PlatformSnapshot` 增加内部退役身份集合。每个被删除账户用原账户 ID 作为仅服务端可见的查找键，保存随机生成的公开匿名 ID、稳定匿名序号和退役时间；不得保存原用户名或原头像的副本。
- 删除账户时，所有保留的用户可见历史把原账户 ID 替换为公开匿名 ID，并写入 `anonymized` 与稳定匿名序号；嵌入的用户名和头像改为非识别回退。Web 根据匿名标记和序号显示“已删除玩家 N”或“Deleted player N”，多个删除玩家保持可区分。
- `historicalSeasons`、`handResults` 的参与者、派彩、玩家结果和摊牌身份使用同一匿名替换规则。内部流水可以保留原账户引用用于守恒和审计，但大厅、房间、普通 HTTP/WebSocket 投影和日志不得返回内部映射或把该引用解释为身份。
- 旧快照缺少退役身份集合、匿名标记或管理投影字段时补空集合/安全默认值；仅加载旧数据不得主动改写历史用户名或头像。只有执行账户删除才匿名化目标。
- 删除历史赛季时同时清理 `seasons`、`historicalSeasons`、该赛季的 `handResults` 和 `ledger`。只被已删除赛季引用的匿名辅助项做引用感知清理；仍被其他保留赛季或当前赛季引用的项继续保留。
- JSON 字段是加法式兼容，不新增 SQL 表或 migration。升级后执行过删除的数据不保证旧应用版本可安全解释；正式降级必须恢复升级前完整 SQLite 备份或使用向前修复，不能直接让旧镜像运行已经发生退役/删除的数据。

### 3.3 平台参赛事实与排行榜

- 在领域层建立游戏无关的最小参赛事实：结果 ID、游戏类型、赛季 ID、参与账户 ID、是否有效和是否撤销。当前扑克适配器从 `HandResultSummary` 生成该事实，不复制牌型、牌面、底池、派彩或下注。
- `currentLeaderboard()` 只选择当前赛季有效、未撤销结果中的当前活动账户；仅加入、观战、作废结果和基础分发行不产生资格，零净变化参与者仍有资格。
- 新赛季归档调用与当前排行榜完全相同的资格和排名函数，然后冻结历史快照。已有历史快照不重新筛选。
- 后续游戏只需向平台参赛事实边界提供等价结果；大厅、排行榜、赛季归档和账户管理不因新增游戏而改写或导入游戏专属类型。

### 3.4 两手间成员与筹码边界

- `Room.seats` 是两手之间的唯一当前成员和筹码来源；进入完整结算、补码、结算撤销和离开时，用一个领域协调路径保持座位筹码与当前已完成扑克状态一致。
- `PokerState.players` 继续保留本手参与者、结算展示、庄家轮转和撤销所需历史，但不得决定已离开或重新加入账户的当前成员资格。
- `startSelectedHand()` 对所有下一手候选只读取当前 `Room.seats` 的筹码与准备/连接状态；旧手玩家映射只可提供不覆盖成员筹码的历史信息。
- `complete` 退出在同一事务中兑换当前座位筹码、移除座位与准备、清除旧玩家对后续投影/选人的影响并广播。重新加入产生新座位买入；同账户 ID 的旧手记录不得覆盖新买入。
- 结算撤销、房主退出、房主踢人、活动手观众退出和活动参赛者禁止自行退出继续遵守现有规则。测试必须覆盖完整结算退出/重进与撤销、重启、重复和过期命令的组合，不能用删除已完成历史来修复成员问题。

### 3.5 删除命令、资产退役和并发

采用以下平台命令名，全部以 `aggregateId: "platform"`、命令 ID、期望平台版本和有效控制租约执行：

| 命令 | 目标 | 执行时规则 |
| --- | --- | --- |
| `account.delete` | 一个不可变账户 ID | 允许目标为发起者；目标缺失或已经删除时明确无变化拒绝。 |
| `account.delete-others` | 执行时除发起者外的全部账户 | 服务端重新计算集合并始终跳过发起者；空集合返回明确 no-op。 |
| `season.delete` | 一个不可变历史赛季 ID | 当前赛季和不存在目标无变化拒绝。 |
| `season.delete-history` | 执行时全部历史赛季 | 服务端只选择历史赛季并保护当前赛季；空集合返回明确 no-op。 |

共同执行顺序如下：

1. 在领域变更前校验租约、平台版本、目标类型和“没有任何未关闭房间”门禁。
2. 批量命令按稳定 ID 顺序建立目标集合，但在一个 `PlatformStore.execute()` 事务内完成；任一目标失败使整批回滚。
3. 删除账户先为当前账户分数写入不可重复的资产退役记录，再移除 `seasonAssets`、`accounts` 和目标租约并匿名化保留历史。守恒计算改为“当前赛季发行量减退役量 = 账户资产 + 桌上资产”，不得把余额转给其他账户。
4. 自删成功结果显式标记 `selfDeleted`，客户端在尝试刷新投影前清除会话和最近账户；删除他人后，其下一次广播、请求或命令由失效租约退出。
5. 删除历史赛季按 3.2 的关联集合一次性清理；当前赛季 ID、资产、账户和其他赛季保持不变。
6. 命令成功增加平台版本并触发大厅广播。重复命令从 `processed_commands` 重放原结果；新命令的过期版本、已删目标、同名新账户或新赛季不能命中旧对象。

### 3.6 Web 平台流程与扑克桌体验

- 大厅投影增加最小账户管理摘要；历史身份投影只包含公开匿名 ID/序号和安全显示字段。平台 UI 不接收租约、流水或退役映射。
- 排行榜使用现有 `SelectField` 模式构建单一可访问赛季选择，选项为当前赛季加按时间倒序的历史赛季；当前选择消失或 current ID 变化时回退当前赛季，并为无合格玩家提供双语空状态。
- 设置中新增独立账户管理和赛季管理入口。逐个和批量确认显示目标/数量、发起者或当前赛季保护、匿名化/永久删除影响和不可撤销说明；按钮、焦点、Esc、触控及 `focus-visible` 沿用共享对话框语义。
- 删除自己成功立即清除 React 会话、房间/大厅状态和 `party-recent-account` 并回登录页；删除他人的客户端通过 `session.replaced` 或失败请求回登录页。
- 错误状态使用结构化的友好中英文说明和可选稳定错误代码。成功、缓存失效和普通同步不显示错误代码、版本、租约或“权威状态”等技术提示；未知错误不显示堆栈和原始内部数据。
- `DeviceControls` 只由登录和大厅渲染。任何游戏等待、进行、暂停、结算、观战或公共展示页面只消费已经选择的设备语言/主题，不拥有切换入口。
- 扑克玩家页删除静音状态的读取、按钮和条件分支，但保留现有阶段提示音与浏览器拒绝保护。移动玩家座位把剩余筹码与本轮下注分成带标签的独立行；桌面投影值和顺序不变。
- 300px 顶部把返回、离开和房主结束操作组织为可换行但不逐个竖排的操作组，房间名称和当前账户身份保持独立布局，不用隐藏关键文本解决重叠。

### 3.7 安全、可观察性、发布和恢复

- 删除授权只依赖服务端租约、版本、房间门禁、目标和保护项；可信 LAN、确认框和隐藏按钮都不替代校验。
- 公共大屏继续匿名只读且不占成员名额；新增历史匿名化不能扩大隐藏牌、账户内部 ID、租约、流水或连接令牌投影。
- 服务日志只记录命令类型、非敏感目标摘要、拒绝码和版本。匿名化映射、原用户名/头像、隐藏牌、deck 和 connection ID 继续禁止记录。
- 本阶段不正式部署、不切换 `home-table`。本地门禁通过后，允许通过既有 SSH 边界让 `npm run test:docker-smoke` 使用 iStoreOS Docker daemon和随机资源前缀；临时容器、镜像标签、端口和命名卷不得使用正式名称。
- 远端 smoke 前后只读记录正式容器镜像/健康、固定卷存在性和正式服务标识。不得进入正式发布目录、覆盖固定备份或调用 `deploy/deploy.ps1`；测试成功后只清理本次已验证的随机资源，清理异常时暂停并保留诊断。
- 隔离卷内覆盖旧 JSON 启动、删除/匿名化持久化、重启后不复现和非 root/health 语义。模拟、本地构建和历史结果不能替代本次远端观察，远端观察也不能描述为正式发布。

## 5. 跨阶段依赖与不变量

虽然路线图只有一个阶段，任务和任意中断检查点都必须满足：

1. 账户/赛季删除 UI 在服务端房间门禁、保护项、事务、匿名化、资产退役和租约失效通过前不可到达。
2. `Room.seats` 始终表示当前成员；已完成 `PokerState.players` 不得重新成为大厅、房间成员或下一手筹码权威。
3. 当前排行榜和赛季归档使用同一平台参赛事实；大厅和设置不得导入扑克细节。
4. 当前赛季始终受保护，批量账户删除始终保留发起者，所有批量操作只有全成或全败。
5. 任何中间状态都必须可加载旧 SQLite JSON，保持现有账户、房间、活动手牌、历史快照、准备恢复和命令信封兼容。
6. 隐藏牌隔离、公共大屏只读、控制租约、资产守恒、幂等、并发和可信 LAN 边界不能因新管理能力放宽。
7. 语言/主题偏好继续生效，但切换入口只属于登录和大厅；平台页面不归入德州扑克组件所有权。
8. 不修改冻结工作流、部署自动化、正式服务、固定数据卷、正式发布目录或唯一备份。

## 6. 最终集成与整体验证流程

验证只在其结果仍有效的最晚位置运行；T2 回改 T1 文件时，在最终门禁中重跑对应分层命令。计划不运行重复的 `verify:core`，也不运行与本功能无关的 `test:deploy`。

1. T1 完成服务端权威后，运行 `npm run typecheck`、`npm run test:platform`、`npm run test:poker` 和 `npm run test:realtime`，证明契约、删除事务、资产、退出/重进、结算撤销、旧状态恢复、租约和私牌投影达到开放 UI 的门禁。
2. T2 完成全部源码和测试后，在最终源码状态依次运行：
   - `npm run lint`
   - `npm run typecheck`
   - `npm run test:platform`
   - `npm run test:poker`
   - `npm run test:realtime`
   - `npm run test:e2e:core`，由该命令完成生产 build 和静态资源无公网引用检查，并覆盖 Chromium 桌面、WebKit 手机及显式 300px 场景
   - `npm run test:capacity`
3. 在上述本地门禁通过后执行用户授权的隔离 `npm run test:docker-smoke`。通过 SSH 使用 iStoreOS Docker daemon、随机临时容器/镜像/卷/端口；前后只读证明正式 `home-table`、固定卷、发布目录和备份未改变。
4. 运行 `git diff --check`，审计实际差异只包含本功能源码、测试、AGENTS 阶段快照和本工作流文件；不得包含生成物、真实配置、冻结历史或部署接口。
5. 汇总全部 `FR-*`、`AC-*` 和 NFR 证据。所有 core 与硬门禁必须通过；`relaxed` 下的 supplemental 异常只有在独立证据证明无交付影响后才能记录为 `FND-I-*`。之后写入不可变阶段结果、`change-0.md` 和 `effective-requirements.md`。

## 8. 风险、技术决策与修订记录

### 8.1 风险与门禁

| 风险 | 控制与门禁 |
| --- | --- |
| 删除账户后资产总量下降却仍按原发行量校验 | 显式资产退役流水和净发行不变量；单个、批量、重复、失败及零余额场景均由 platform/server 阻塞测试覆盖。 |
| 匿名化仍能通过原 ID、名字或头像恢复身份 | 用户可见历史换为随机公开匿名 ID和本地化序号；内部映射不投影、不记录日志；同名重建和重启场景验证。 |
| 永久赛季删除留下悬空引用或误删当前赛季 | 服务端 current 保护、按 season ID 清理、引用感知匿名辅助清理和单事务回滚；无 UI 单独绕过路径。 |
| 完整结算退出与结算撤销/重新加入竞争破坏筹码 | 座位作为两手间权威，旧扑克记录仅保留历史；覆盖退出、撤销、重进、开手、重启和过期版本的组合测试。 |
| 被删客户端继续控制平台 | 删除事务移除租约；广播、HTTP 和下一命令均验证失效；自删在客户端刷新前清会话。 |
| 平台 UI 被继续实现为扑克专属 | 新平台 UI 文件和平台契约不得导入牌型、底池、下注或扑克组件；差异审计和类型依赖检查阻塞。 |
| 新数据使旧镜像降级失败 | 本阶段不正式切换服务；隔离卷测试。正式升级后若已发生删除，降级必须恢复升级前完整备份而不是直接运行旧代码。 |
| 远端测试误触正式资源 | 随机资源前缀、前后只读正式资源审计、无 deploy 入口、无固定卷/备份挂载；清理失败立即暂停。 |

### 8.2 技术决策

| 决策 | 结论 | 依据 |
| --- | --- | --- |
| 路线图形态 | `single` | 一个加法 JSON/命令/UI 集成可在单一可恢复阶段完成，没有兼容双写或外部交付边界。 |
| 计划细节 | `expanded` | 永久删除、匿名化、资产退役、公开投影和降级恢复属于合同列明的高风险条件。 |
| 平台参赛边界 | 使用游戏无关最小事实，当前扑克结果作为适配器 | 用户明确要求德州扑克只是当前游戏，平台排行榜不能拥有扑克内容。 |
| 匿名身份 | 内部原 ID → 随机公开 ID/稳定序号；不保存原显示资料副本 | 同时满足历史结构、不可还原、多人可区分和同名重建隔离。 |
| 持久化 | 扩展现有 JSON，不新增 SQL 表 | 现有快照事务和启动归一化已提供所需原子/兼容边界。 |
| 批量语义 | 服务端执行时计算目标并单事务提交 | 防止客户端旧列表、保护项变化和部分删除。 |
| 远端验证 | iStoreOS 隔离 Docker smoke，不发布正式服务 | 用户明确授权测试；需求仍排除正式切换和固定数据资源修改。 |
