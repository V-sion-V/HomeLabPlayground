## 1. 当前目标与范围

本功能在既有家庭局域网聚会游戏平台和完整德州扑克产品之上，提供房主踢人/退出与自动转让、牌中加入与观战、首局/后续手牌统一准备、持久化动态筹码面值、设置界面重构、设备级亮暗主题、主界面/扑克配色分离和配置化头像。

当前范围包括等待、活动、暂停和完整结算阶段的成员生命周期；SQLite JSON 快照兼容恢复；桌面、触控、键盘、300px 窄屏与简体中文/英文；匿名公共大屏兼容和服务端私牌隔离。

当前范围不包括其他游戏规则、匹配、机器人、聊天、互联网身份或管理后台；不改变 2–10 人德州扑克上限、公共大屏多开和花色预设语义；不提供主题/头像在线管理或热更新；不修改自动化部署功能。产品仍只适用于可信家庭 LAN，不得直接暴露公网。

## 3. 当前流程

### 3.1 等待房间和首局

1. 房主创建房间并自动成为必定参赛成员。
2. 其他成员买入加入并准备或取消准备。
3. 房主加至少一名在线、有筹码、已准备成员后可开始。
4. 若存在未准备成员，房主先确认其将进入观众席；取消不发送开手命令。
5. 服务端按提交时版本和权威成员/连接/筹码/准备原子建立手牌、保存面值快照并清空准备。
6. 未准备成员保留房间资格和买入，以观众身份查看公开牌桌。

### 3.2 牌中加入和观战

1. 登录用户在大厅选择未满活动房间并输入合法买入。
2. 服务端原子预留名额、转入买入、冻结排行榜并建立非参赛成员。
3. 用户看到公共大屏级牌桌；顶部显示本人身份、返回/退出、语言和主题。
4. 观众没有私牌、下注、行动、摊牌选择或庄家资格。
5. 当前手进入 `complete` 后，观众自动进入结算/准备界面，可补码、准备、取消或退出。

### 3.3 完整结算和下一手

1. `complete` 阶段的新成员直接进入结算/准备界面。
2. 非房主成员选择准备，房主自动参赛。
3. 房主达到最少两名参赛者条件后显式开始。
4. 未准备成员存在时二次确认；确认后只选择房主和有效准备成员。
5. 下一手从最新全局面值建立新的不可变快照。

### 3.4 踢人、退出和关闭

1. 房主点击非房主头像打开转让/踢出菜单；踢出确认显示目标用户名。
2. 服务端事务处理强制弃牌、底池保留、剩余筹码兑换、成员/准备移除和后续行动或结算。
3. 房主顶部退出确认后，服务端按相同资产语义移除房主并随机选择在线继任者。
4. 没有在线候选时，服务端作废未结算手牌、退款、兑换并关闭。
5. 观众可随时退出并取回未参赛买入；普通当前参赛者牌中不能自行退出。

### 3.5 全局设置、主题与头像

1. 打开全局设置时游戏卡片默认收起；标题和底部操作保持可见。
2. 展开扑克卡片，编辑盲注、买入、花色和合法面值后保存；完整设置一次性校验并持久化。
3. 活动手牌继续使用旧面值快照，完整结算后切换最新全局设置。
4. 主题按钮切换当前设备的主界面或扑克语义调色板并写入本地存储。
5. 创建/编辑账户只显示配置头像；旧失效当前头像由服务端恢复为不可选回退值。

## 4. 当前数据、接口与状态

- `GlobalSettings.poker.denominations` 保存规范化全局面值，合法范围为 1–16 个唯一正安全整数且包含 `1`。
- `PokerState.denominations` 保存活动手牌快照。活动阶段投影使用该快照；waiting/complete/void 使用最新全局值。
- `Room.seats` 保存全部已买入、计入 10 人上限的成员；`PokerState.players` 只保存当前手参赛者。
- `Room.waitingReadyAccountIds` 保存首局易失准备；`PokerState.readyAccountIds` 保存完整结算后的易失准备；服务端投影为统一准备语义。
- `PublicSeatProjection.role` 区分 `member`、`participant` 和 `spectator`；`RoomProjection.viewerRole` 区分 `member`、`participant`、`spectator` 和 `display`。
- `RoomProjection.effectiveDenominations` 是客户端唯一应使用的当前面值来源。
- `room.join` 支持 waiting、in_progress 和 paused；`poker.ready` 支持显式 `ready: boolean`；旧客户端省略时等价 `true`。
- `room.start` 可携带 `pokerVersion` 和 `confirmUnready`，但确认框不替代服务端版本与资格校验。
- `room.remove` 和 `room.leave` 仍在现有命令 ID、期望平台版本、控制租约和 SQLite 事务边界内执行。
- 主题偏好仅保存在浏览器本地，不进入账户、SQLite、房间投影或 WebSocket。
- 头像配置由服务器和 Web 客户端消费同一共享模块；当前账户头像持久化，历史头像快照保持不可变。

## 5. 当前异常、边界、安全与恢复

1. 重复、过期、并发或持久化失败的加入、准备、开手、踢人、退出、转让和设置命令必须完整回滚，不得重复转移资产或形成部分成员状态。
2. 确认框打开后目标、房主、准备、连接、筹码或版本变化时，提交必须按当前权威状态拒绝或重新验证。
3. 加入在买入不足、房间满、房间关闭、账户已在其他房间或持久化失败时不转移资产。
4. 观众退出和关闭房间退回未参赛完整买入；已参赛成员按权威桌上筹码兑换。
5. 房主退出候选只取执行时在线的其他成员；随机选择和房主变更在同一事务。无候选走作废、退款、关闭路径。
6. 被踢者若正在行动，扑克引擎强制弃牌并继续到下一合法行动者或结算，不留下阻塞行动位。
7. `showdown` 和 `distribution` 在进入 `complete` 前仍是活动手牌，新成员只能观战且面值保持当前手快照。
8. paused 的 `complete` 房间允许加入，但只有恢复到可开手状态后才能开始下一手。
9. 房主筹码为零时不能开手，必须先补码；失败不改变成员、观众或准备状态。
10. 服务重启恢复成员、观众、买入、资产、活动手牌和面值快照；全部连接与准备归一化为离线、未准备。
11. 旧数据缺少全局/每手面值、成员准备或有效头像时兼容补齐；失败不得以部分状态启动。历史头像快照不迁移。
12. 观众和 display 只接收公开牌桌主体；只有持有有效控制租约且属于当前 `PokerState.players` 的本人可接收 `ownHoleCards` 和行动能力。
13. 无效头像更新、无效面值或无效配置必须原子拒绝；配置结构缺失必须受控失败，不得静默回退到扑克绿色主界面。
14. 自定义 listbox、折叠、动画或主题切换失败不得改变服务端牌局权威；刷新后可从服务端恢复。
15. 正式生产 Docker 服务和固定数据卷不属于功能运行时测试资源；升级仍须通过受支持的自动化部署入口和独立授权。
