# 阿瓦隆游戏：实施路线图

## 1. 范围与执行模式

- 功能编号：`avalon-game`
- 合同版本：`3.2`
- 需求文档：[requirements.md](requirements.md)
- 执行模式：`single`
- 详细程度：`expanded`
- 交付与验证策略：`relaxed`
- 路线图修订：`1`
- 需求指纹：`sha256:7b27e53479b995e9aa5decb9a73f29f91ee015cd7ad9a7ec56765d14765b936d`
- 项目基线：`main@67e68cea036a41c38917e19936c27e3f7cd49f19`
- 创建日期：`2026-07-31`

本功能使用一个阶段完成有符号积分兼容、阿瓦隆纯规则引擎、共享游戏判别、平台领域与
SQLite 恢复、Fastify 命令和角色投影、玩家/管理员/公共大屏界面及最终验收。Web 和
服务端由同一生产容器同步发布；共享 `Room` 判别、阿瓦隆命令和客户端调用不存在需要
维持的旧客户端兼容期，也没有 SQL 双写或可单独发布的迁移中间态。把它拆成多个可发布阶段
会留下“服务端接受阿瓦隆但 Web 不能完整操作”或“新有符号快照由旧不变量解释”的不安全
状态，因此采用 `single`。

选择 `expanded` 是因为本功能同时改变全平台资产符号语义、账户删除/退役、扑克买入边界、
房间判别联合、活动秘密恢复与按租约投影，并新增完整多人秘密状态机。阶段内设置三个有序
任务检查点：先建立纯规则和有符号基础，再接入平台/服务端权威边界，最后交付 Web 和完整
验收；任务是恢复与验证边界，不是独立发布阶段。

`relaxed` 允许实现先于测试，不要求红灯优先。全部 core 验收、项目硬门禁、资产守恒、
安全整数、角色/投票/任务隐私、租约、并发、恢复、扑克兼容、构建和离线运行仍阻塞完成。
只有独立证据证明不影响交付功能的 supplemental 异常可以按连续 `FND-I-*` 编号报告。

规划前工作区唯一变化是用户提供且未跟踪的
`docs/requirements/avalon-game/requirements.md` 与 `workflow-contract.md`。本路线图
接管本功能后续工作流工件，不改写其他已冻结 feature 历史，也不把这两份输入冒充为实现
修改。

## 3. 全局详细设计

### 3.1 共享判别联合与包边界

1. `@party/contracts` 定义 `GameType = "texas-holdem" | "avalon"`，并分别提供
   `PokerRoomConfig`、`AvalonRoomConfig`、`PokerRoom`、`AvalonRoom`、
   `PokerRoomProjection`、`AvalonRoomProjection` 和对应大厅摘要。`Room`、
   `RoomProjection`、`LobbyRoomProjection` 只作为判别联合，不用大量可选游戏字段容纳
   非法混合状态。
2. 共享房间基类只包含 ID、名称、状态、房主、成员在线/座位、局间准备、平台版本、创建
   时间和房主断线时限。扑克成员和投影保留筹码字段；阿瓦隆成员/参与者只包含公开身份、
   在线、座位和角色无关状态。
3. 新 `@party/avalon` 只依赖共享类型和可注入的随机顺序，不访问 SQLite、HTTP、DOM 或
   账户资产。它暴露不可由客户端绕过的配置验证、状态创建和版本化状态转换函数。
4. 服务命令按命令族和房间 `gameType` 双重收窄。跨游戏、缺少判别、缺少游戏版本或非法
   payload 在修改前稳定拒绝；正式 Web 与服务端同步升级，不承诺旧客户端长期兼容。

### 3.2 有符号安全整数、流水和扑克兼容

- 账户分数、赛季基础分、冻结排行榜分数、历史分数及每局净变化必须用
  `Number.isSafeInteger` 校验。比较排行榜时使用关系比较而不是可能溢出的数值相减。
- 所有加减在写回前使用 checked arithmetic。账户可跨零并变负；押分、扑克买入、补码、
  栈、下注、底池、托管和流水单条金额必须是非负安全整数。
- 正基础分使用“赛季发行 → 账户”，负基础分使用“账户 → 赛季负债发行”；删除正分账户
  使用“账户 → 资产退役”，删除负分账户使用“负债退役 → 账户”，金额均取非负绝对值。
  守恒式按方向汇总发行资产、发行负债、退役资产和退役负债，再与账户及游戏内资产总和
  比较；任何中间和总和不安全即拒绝。
- 扑克加入和补码移除余额充足检查，但继续校验正安全整数、最小/最大买入、桌上限额、
  时点、版本和非负游戏资产。既有扑克状态机、私牌、结算和撤销语义不得改变。
- 阿瓦隆开局从每个冻结参与者账户向本局托管转移同额押分；余额不构成门禁。终局或作废
  在同一领域/存储事务中派分或退款，任何失败回滚完整命令。

### 3.3 阿瓦隆设置、配置和房间生命周期

1. `GlobalSettings.avalon` 保存默认认角色模式、默认奥伯伦规则、默认押分和
   `5`–`10` 六套角色预设。新安装使用需求默认；旧快照缺失时只补该分组并在恢复事务中
   持久化。
2. 管理员保存仍是一个 `admin.settings.update`：通用、扑克和全部阿瓦隆预设先完整校验，
   任一非法值使整个命令无变化。预设按人数独立验证但作为一个对象原子提交。
3. 创建阿瓦隆房间时冻结房间自己的模式、角色来源/角色列表、奥伯伦规则、押分和房主转让
   时限；管理员之后的修改不暗改房间。房主只可在等待或完整结算的局间更新下一局配置。
4. 阿瓦隆房主加入后自动准备；其他在线成员显式准备。开始时选择房主和在线已准备成员，
   要求 `5`–`10` 人，未准备成员需房主确认并成为观众。活动局加入者只成为观战成员。
5. 活动参与者退出、被移除/删除、房主作废或无在线房主候选时，先原子作废并处理全部托管，
   再处理成员、房主或账户。房主身份与游戏队长顺序始终独立。

### 3.4 纯阿瓦隆状态机

- 配置验证固定原版善恶人数、五项队伍人数、第四项双失败阈值、梅林/刺客必选、特殊角色
  唯一、普通角色补位和 5 人派西维尔搭配约束。
- 开局冻结参与者/座位、配置、随机角色、随机起始队长、押分和版本。状态显式区分
  `role-confirmation`、`manual-night`、`team-proposal`、`team-vote`、
  `mission`、`assassination`、`complete` 与 `void`；房间暂停不覆盖内部阶段。
- 自动知识只返回规则允许的不可区分账户集合；手动模式只返回本人角色。夜间步骤按实际
  角色和奥伯伦规则生成，可在第一次提名前由房主重启，之后不可重启。
- 全员确认后进入提名；当前队长提交准确人数的唯一队伍；全体参赛者秘密投票，全员后一次
  公开个人票。平票否决，五次连续否决邪恶立即获胜。
- 通过队伍仅允许成员提交任务；善方只可成功，邪恶可成功/失败。全员前只公开数量进度，
  完成后仅保存/投影汇总，不保留可公开关联到提交者的顺序。
- 三次失败立即邪恶胜；三次成功进入刺杀。只有刺客本人可从除自己外的全部冻结参与者中
  提交一次目标；命中梅林邪恶胜，否则善方胜。
- 每个转换要求期望阿瓦隆版本并只增加一次版本。重复 command ID 由 store 重放，过期/
  并发由平台和游戏版本拒绝；断线不会触发任何自动行动。

### 3.5 投影、隐私、日志和控制租约

1. 活动原始角色映射、知识、票、任务选择和刺杀目标只保存在恢复状态。领域根据 viewer
   的账户、有效租约、参与/观战身份、模式和阶段构造投影；原始状态永不直接序列化。
2. 参与者只取得本人角色、自动模式允许的知识以及本人已提交标志；其他玩家、房主、观众、
   display、管理员和大厅只取得公共子集。公开进度使用计数或提交标志，不含未公开值。
3. 完整结算公开全部角色、阵营、胜因和分数；作废不公开角色。恢复和删除路径必须保留该
   区分。
4. 增加等价于私牌断言的 `assertNoAvalonSecrets`，对大厅、管理员、display 和非本人投影
   做序列化边界检查。Fastify 日志 redact 覆盖角色映射、知识、票、任务、刺杀目标和连接
   令牌；结构化拒绝日志只保留命令类型、版本和稳定错误码。
5. 控制接管立即使旧 lease 无法获取私有投影或提交动作；浏览器本地遮盖在后台、刷新、
   重连、接管和离开时重置，但不改变服务器上的合法私有知识。

### 3.6 结果、删除、恢复和兼容

- `AvalonResultSummary` 保存正常/作废结果所需的公开终局、角色、阵营、流程摘要、净变化、
  结算后分数和参与者；`participationFacts()` 聚合扑克与阿瓦隆，只有正常且未撤销结果有效。
- 账户删除前若目标是活动阿瓦隆参与者，先作废退款；之后以正/零/负退役方向处理资产，
  清租约并匿名化排行榜、扑克结果和阿瓦隆公开结果。整个管理员命令全成或全败。
- 历史赛季删除同时清理阿瓦隆结果和相应流水；未被剩余历史引用的匿名身份才可清理。
- 重启保留角色、已提交票/任务、公开历史、托管和内部阶段；清除租约、连接和局间准备。
  活动角色确认事实可保留，设备遮盖不持久化。旧扑克快照原值恢复且不会被转换成 Avalon。
- 正式回退仍依赖现有升级前完整 SQLite 备份；本 initial 不改 Docker 卷、发布目录、部署
  状态机或正式服务。

### 3.7 Web、管理员和公共大屏

1. 大厅创建先选游戏。扑克表单保留原字段；阿瓦隆表单提供模式、预设/自定义角色、
   奥伯伦规则和押分。房间卡按 `gameType` 展示正确摘要；加入阿瓦隆不显示买入。
2. 管理员游戏设置增加可折叠阿瓦隆卡：默认模式、奥伯伦、押分和 5–10 人预设编辑器。
   客户端即时提示与服务端规则一致，但服务端仍是最终权威。
3. 阿瓦隆房间复用统一房间顶栏和成员管理；等待/结算允许配置、准备和开始。活动玩家页用
   上方参与者、中间五项任务局势、下方上下文操作；观战成员保持只读公共视图。
4. 私密角色区默认遮盖并通过显式按钮查看/隐藏。`visibilitychange`、卸载/房间切换、
   WebSocket 重连和 session replacement 重置本机显示。投票、任务和刺杀草稿仅在本机，
   权威版本或阶段变化时清空并提示。
5. 手动夜间步骤在房主端和 display 显示；自动模式 display 只显示确认进度。display
   始终匿名、只读、不占名额，活动期不渲染任何秘密或控制。
6. 全部新增固定文案、角色、阶段、规则、错误和胜因提供中英文；复用账户主题、音量、
   `FixedPanel`、`Modal`、portal 与 `focus-visible`。300px、十名玩家、长文本和角色
   编辑不产生页面级横向滚动，信息不只靠颜色或动画。

### 3.8 验证、隔离环境和交付

- 新增 `npm run test:avalon`，纯规则矩阵和不变量由该套件独立证明；平台、服务、实时、
  poker、E2E、capacity、build/static 和 Docker smoke 各自只承担其对应边界。
- 最终本地源码门禁通过后，在用户授权的 `192.168.100.1` 上使用随机镜像、容器、命名卷、
  临时归档和端口验证 `linux/amd64`、非 root、health、离线启动、旧快照归一化、阿瓦隆
  恢复和浏览器核心流程。不得切换 `home-table`、固定卷、正式发布目录或唯一备份。
- 远端验收前后只读比较正式容器/镜像/健康、固定卷存在性和已知发布标识，不读取业务
  SQLite。只清理能由随机前缀精确证明属于本次的资源；归属不确定则暂停并保留现场。
- initial 工件一致收口后，仅暂存本功能解释的文件，创建用户要求的 Git 提交并推送当前
  `main`。推送不等同于正式 iStoreOS 发布。

| 阶段 | 目标 | 关联需求与验收 | 前置阶段 | 退出条件 | 当前状态 |

| P-001 | 交付完整阿瓦隆、全平台有符号积分及其本地和隔离 iStoreOS 验收 | FR-001–FR-058；AC-001–AC-031；NFR-001–NFR-012 | 无 | 三个有序任务完成；全部 core 和硬门禁通过；supplemental 通过或仅有合规 `FND-I-*`；远端随机资源已清理且正式资源不变；initial 工件一致收口 | ready |

## 5. 跨阶段依赖与不变量

虽然路线图只有一个阶段，三个任务和任意中断点都必须满足：

1. 账户分数可以为负，但所有账户值、基础分、净变化和中间总和必须是安全整数；游戏资产
   和流水金额不得为负。
2. 任一积分、押分、扑克或退役命令在守恒、溢出、版本、幂等或持久化失败时全成或全败。
3. Poker/Avalon 房间、配置、状态、命令、投影和结果保持判别一致；跨游戏调用不修改状态。
4. 活动阿瓦隆秘密只进入本人有效租约投影；大厅、管理员、其他玩家、观众、display 和日志
   永不获得越权秘密。完整结算公开、作废不公开。
5. 房间房主、阿瓦隆队长和刺客权限互不替代；断线不自动行动，房主转让不改变游戏顺序。
6. 旧 SQLite 快照、扑克房间/手牌、账户偏好、排行榜、管理员、公共大屏和部署接口在任意
   已完成任务检查点保持可构建、可恢复。
7. 服务端/领域是配置、角色、阶段、合法动作、积分和权限的唯一权威；Web 草稿、遮盖、
   动画和隐藏按钮不决定业务状态。
8. 公共大屏匿名只读且不占名额；局中加入者和未准备成员不进入当前参与者、投票或任务集合。
9. 新文案双语，300px、键盘、触控、`focus-visible`、减少动态和运行时离线要求不放宽。
10. 不修改其他 feature 的冻结工件、真实部署配置、正式服务、固定卷、正式发布目录、
    唯一备份或未知恢复现场。

## 8. 风险、技术决策与修订记录

### 8.1 风险与检查点

| 风险 | 控制 |
| --- | --- |
| 有符号总量或中间算术溢出 | 单一 checked arithmetic 边界；极值、正负发行/退役、扑克透支、阿瓦隆托管/派分和回滚测试。 |
| 判别联合迁移遗漏旧扑克调用方 | T2 编译门禁、跨游戏拒绝、旧快照恢复和完整 poker 回归；不以可选字段绕过类型。 |
| 活动秘密经 projection、日志或错误泄漏 | 角色化构造、序列化泄漏断言、不同租约/观众/display/admin 测试和日志捕获。 |
| 任务选择通过顺序或持久结构关联玩家 | 引擎只在活动私有状态保存提交映射，公开历史只存汇总；广播前全员统一转换。 |
| 活动参赛者删除造成孤立托管或公开角色 | 同一 store handler 先作废退款再离房/退役；失败注入与作废投影阻塞。 |
| 重启重复分配、托管或派分 | 恢复只归一连接/准备，不调用开局或结算；持久状态/command replay/lease 重建测试。 |
| 300px 或十人状态不可操作 | 固定容器、可换行/网格、语义文字、Chromium/WebKit 和远端浏览器真实布局检查。 |
| 远端测试误触正式资源 | 随机前缀、临时端口、精确 inspect、前后只读比较；无法证明归属时停止清理并暂停。 |

### 8.2 技术决策

- 使用独立 `packages/avalon`，不把规则复制到 Fastify 或 React。
- 继续使用版本化 JSON 快照，不新增 SQL 表或运行时依赖；这是可加法升级且与现有事务/
  Docker 卷边界相容的最小方案。
- 共享类型采用判别联合，同时保留必要的扑克类型别名以机械迁移现有调用者；类型别名不能
  允许 Avalon 携带扑克状态。
- 公开任务历史保存个人公开投票，但任务卡只保存汇总；活动秘密恢复状态与公开结果分离。
- 正式部署不属于 initial。用户授权仅用于隔离部署环境测试；Git 推送发生在工作流收口后。
