## 1. 当前目标与范围

平台当前同时支持德州扑克和 5–10 人原版阿瓦隆。阿瓦隆包含自动/手动认角色、原版与
Dized 奥伯伦、管理员 5–10 人预设和房主自定义角色、固定五任务、秘密投票与任务、刺杀、
押分结算/作废、排行榜参赛事实、SQLite 恢复，以及玩家/观战/匿名 display 的中英文响应式
体验。当前玩家端以玩家卡承载临时身份、提名和行动状态，以固定五任务轨迹承载规则与
进度；阿瓦隆使用独立于德州扑克的冷色主题。固定页面在手机动态视口内只有一个纵向
滚动所有者，房主管理动作通过玩家卡上下文菜单提供。

账户分数、赛季基础分、排行榜和历史使用有符号 JavaScript 安全整数；Poker/Avalon
游戏资产、押分、筹码、下注、底池和单条流水金额继续为非负安全整数。服务端、领域与
SQLite 事务是配置、秘密、合法动作、胜负和资产的唯一权威。

当前不包含其他扩展角色/变体、机器人、聊天/语音、永久逐局回放、密码/公网身份、部署
状态机改造或正式 `home-table` 发布。

## 3. 当前流程

### 3.1 管理员与创建

1. 可信 LAN 用户可直接进入 `/admin`，原子编辑通用、Poker 和 Avalon 设置。
2. Avalon 设置包含默认自动/手动模式、默认 `original`/`dized` 奥伯伦、默认押分 100，
   以及 5–10 人各一套唯一预设；任一非法配置使整次保存无变化失败。
3. 玩家在大厅先选择只含图标和醒目游戏名的游戏卡。Avalon 房主选择管理员预设或服务端
   验证的自定义角色，创建后可在局间修改；活动局使用不可变配置快照。
4. 加入 Poker 或 Avalon 前均以居中大字显示房间名、本地化游戏名和当前人数；Poker
   继续显示买入范围及输入，Avalon 不出现买入控件。

### 3.2 加入、准备与认角色

1. 房主自动准备；其他成员准备/取消。准备区用同一行十个圆点表示当前人数，已占用从左
   填充，空的前五位为实线、后五位为虚线；准备玩家卡使用操作提示色。5–10 名在线准备者
   由房主明确开局，未准备者和局中加入者只观战；开始按钮与相邻设置保存区贴底对齐。
2. 开局事务托管每人同额押分、冻结参与者/座位/配置，并随机分配角色和首任队长。
3. 自动模式由私人设备显示本人角色和规则允许的知识；手动模式只显示本人角色，房主和
   display 推进按实际组合生成的双语夜间步骤。
4. 左下只保留较窄的“查看身份”按钮；确认身份前按钮可强调，确认后恢复次要样式。按住
   期间所有玩家卡使用相同强调填充，只有本人及规则允许知道的对象显示文字，本人卡始终
   显示精确角色；松开后消失。私人信息默认遮盖，在后台、刷新、重连、接管、离房和权威
   状态变化时重新遮盖；每人独立确认角色，房主不能代确认。

### 3.3 提名、投票、任务与刺杀

1. 当前队长把上方参赛玩家卡直接作为可聚焦、可触控的选择按钮；提名期间整个“本局参赛”
   区域使用操作提示强调边框呼吸，减动效时保留静态边框。选够当前任务要求的人数后在
   右下提交；选中卡变色并具有 `aria-pressed`。所有参赛者秘密投票，待投票卡使用操作
   提示色；提交后恢复普通背景并显示“已投票”，全员提交后同时公开个人票。
2. 严格多数通过；否决轮转队长，第五次连续否决立即邪恶胜。
3. 通过后只有队员提交任务；待提交卡使用操作提示色，善方只能成功，邪恶可成功/失败。
   全员前只公开计数，完成后恢复普通背景并只公开成功/失败汇总；任务轨迹以绿色/红色
   实心结果卡和放大票数呈现，不重复“任务成功/失败”文字。
4. 三次失败邪恶胜；三次成功进入刺杀。仅刺客从除本人外且不标阵营的冻结参与者中选择
   一次目标；命中梅林邪恶胜，否则善方胜。

### 3.4 结算、作废与下一局

1. 正常终局在同一事务返还胜方自身押分、按座位稳定均分败方押分、保存公开结果和有效
   参赛事实；净变化总和为零。
2. 完整结算公开全部角色、胜因、每人变化和结算后总分，并保持到房主明确开始下一局。
3. 活动参赛者退出/移除/删除、房主作废或安全关闭先原子作废并退款；作废不公开角色、
   不产生有效参赛事实。
4. 需要某玩家行动而其断线时无限等待；房主可暂停、恢复或作废，不存在自动代投或倒计时。

### 3.5 玩家页状态层级

1. 上方玩家卡用独立辅助色边框标记本人、用操作提示强调色边框标记队长；二者重合时只
   显示优先级更高的队长色。准备或当前待行动状态使用操作提示色背景，同时保留文字提示。
2. 中间五任务不显示可见序号或标题下成功/失败总数；未完成项含当前项只显示队伍人数和
   失败阈值，当前任务使用操作提示强调色；完成项只显示成功/失败票数，并分别用高对比
   绿色/红色实心背景和对比文字。
3. 桌面和手机都让左侧查看区较窄、右侧当前行动区较宽并保持同一行；手机把右卡内的
   同意/反对、成功/失败等二选一按钮纵向排列。轮到当前玩家时右侧整卡填充操作提示色，
   内部按钮使用其他高对比颜色，页面没有横向溢出。
4. 固定壳层使用动态视口高度，页面外层与内部内容区不会同时成为纵向滚动所有者。Avalon
   与 Poker 的房主管理入口不常态显示，只从非本人玩家卡的长按、右键或键盘上下文菜单
   打开；菜单通过 portal 定位并支持 Escape、外部点击和焦点恢复。

## 4. 当前数据、接口与状态

- `GameType` 至少为 `texas-holdem | avalon`。Room、RoomConfig、RoomProjection、
  result 和命令 payload 使用严格判别联合，不允许混合非法字段。
- `GlobalSettings.avalon` 保存默认模式、奥伯伦、押分和 5–10 人预设；旧快照缺失时补
  当前默认值并持久化，不改变旧 Poker 状态。
- Avalon 活动快照保存冻结配置/参与者/座位、角色、知识规则、当前任务/队长、队伍、
  私密票/任务、公开历史、否决/任务轨迹、夜间步骤、刺杀、托管、版本和终局。
- 外部写命令覆盖设置、准备、开局、角色确认、夜间推进/重启、队伍、投票、任务、刺杀、
  暂停/恢复、作废、离开/移除，并携带命令 ID、期望平台版本和期望 Avalon 版本。
- SQLite 继续使用 WAL、版本化 JSON 快照和 `processed_commands`，在单事务中同时保存
  资产、领域状态、流水、结果和幂等响应；没有新增 SQL 表或改变 `/data` 卷接口。
- 正常 Avalon 结果提供游戏无关参赛事实；作废结果无效。账户删除匿名化保留公开结果，
  历史赛季删除清理结果和关联流水。
- Web 主题配置提供 `main`、`poker` 和 `avalon` scope；Avalon light/dark 使用独立冷色
  调色板，玩家端和匿名 display 都按房间类型选择相同 scope。

## 5. 当前异常、边界、安全与恢复

- 人数/阵营/角色唯一性、必选梅林/刺客、5 人派西维尔搭配、队伍人数、阶段、行动者、
  善方失败牌、刺客身份、押分和安全整数均由服务端无变化拒绝。
- 重复、过期、跨游戏、并发、持久化失败、守恒差额、负游戏资产或溢出不能产生部分托管、
  派分、流水、结果或阶段推进。
- 活动角色、知识、未公开票、任务选择和刺杀目标不进入大厅、管理员、其他玩家、观战、
  display 或普通日志；完整结算公开与作废不公开是不同投影边界。
- 刷新、断网、接管和服务重启恢复相同角色、秘密提交、公开历史、托管和阶段；旧租约失效，
  连接/局间准备安全归一化，本机显示重新遮盖，未提交草稿不持久化。
- 正、零、负账户删除保持方向明确的发行/退役守恒、租约失效、结果匿名化和同名隔离；
  活动参赛者先作废退款，整组命令全成或全败。
- 正式回退依赖升级前完整 SQLite 备份；不得让旧镜像解释新负分状态，也不得删除固定卷、
  固定备份或未知恢复现场。

## 8. 当前决策

- 交付策略为 `relaxed`；core 和硬门禁阻塞，supplemental 仅可在独立证明无交付影响时保留
  report-only finding。initial、change-1 和 change-2 最终均为 `passed`，没有 finding。
- 初版只支持原盒角色与固定五任务；每人数一套管理员预设，房主可选预设或自定义。
- 默认自动模式、`original` 奥伯伦和押分 100；押分至少 2，账户余额不构成开局门禁。
- 全平台采用有符号账户分数方案；内部游戏金额和资产继续非负。
- 阿瓦隆使用独立冷色 light/dark 调色板；操作提示强调色统一表示准备/当前待行动、队长、
  当前任务和提名事件，本人边框使用独立辅助色；本人和队长重合时队长边框优先。
- 临时私人知识和提名选择都直接绑定上方玩家卡；底部区域只保留查看入口、选择摘要和
  权威命令提交，不重复玩家信息或候选网格。
- 固定页面使用动态视口与唯一纵向滚动所有者；房主管理动作不常驻玩家卡，只通过触控
  长按、桌面右键或键盘上下文菜单打开 portal 菜单。
- 正式部署不属于本需求。2026-07-31 隔离验收完成后，正式 `home-table` 仍运行 Git
  `67e68cea036a41c38917e19936c27e3f7cd49f19`。

## 9. 已替换或退役项目

change-0 没有删除已批准的 FR、AC 或 NFR。被替换的是旧的隐式业务假设：

- “平台只有 Poker 房间”已由严格 `GameType` 判别替换。
- “账户分数不得低于零/买入必须有足够余额”已由有符号账户分数和非负游戏资产边界替换。
- “阿瓦隆仅是未来复用目标”已由当前完整游戏能力替换。

change-1 进一步替换以下旧 UI 表达，但不改变底层规则或投影权限：

- 中文界面中的系统 `Avalon` 标签已由“阿瓦隆”替换；游戏选择卡的默认规则副标题已退役。
- 加入层的小号左对齐游戏名已由居中的房间名、游戏名和当前人数摘要替换。
- `2/5–10` 文本人数提示已由十个带占用/实线/虚线语义的圆点替换。
- 左下角色/知识详情和右下候选人网格已分别由玩家卡临时覆盖和玩家卡原生选择按钮替换。
- 共用 Poker 绿金主题已由独立 Avalon 冷色主题替换。

change-2 进一步替换以下旧 UI 表达，但不改变底层规则、命令或投影权限：

- 固定壳层与页面外层的双层纵向滚动已由动态视口和唯一滚动所有者替换。
- “查看私密信息”及只点亮已知对象的表达已由“查看身份”、全卡统一强调和本人精确角色
  覆盖替换；确认身份后按钮不再持续强调。
- 手机底部单列已由左窄右宽双列替换，右侧二选一操作在卡内纵向排列。
- 任务序号、标题下结果总数、浅色结果、完成项规则和“任务成功/失败”文字已由简化规则、
  放大票数及高对比绿色/红色实心结果卡替换。
- 独立队长色以及本人使用操作提示色的边框方案已由队长/当前任务共用操作提示强调色、
  本人使用独立辅助色的方案替换。
- Avalon 常驻房主管理按钮和 Poker 普通左键头像菜单已由长按、右键与键盘上下文菜单替换。

这些替换不恢复旧行为；后续变化必须通过新的连续 `change-N` 记录。
