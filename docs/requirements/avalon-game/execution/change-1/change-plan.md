## 3. 影响分析与全局设计

1. 为 `productConfig.themes` 增加 Avalon light/dark scope，扩展 `ThemeScope`，并按当前
   `room.gameType` 选择 main/poker/avalon；display 在取得房间投影后使用相同判别。
2. 共享大厅增加本地化 Avalon 名称和统一加入摘要。用户输入的房间名保持原值，不对用户
   内容做翻译；“全局中文 Avalon”只约束系统拥有的产品标签和标题。
3. `AvalonMemberRail` 接收本地私密覆盖和队长提名选择状态。覆盖值只能由当前 viewer 的
   `ownKnowledge` 生成；公共 display 不传入该数据。选择按钮只在当前 viewer 是有效队长且
   阶段允许时出现，服务端继续最终校验。
4. 任务规则直接消费 `@party/avalon` 的 `AVALON_RULES`，不在 React 复制人数矩阵，也不
   改变网络投影。
5. CSS 在 Avalon scope 内定义操作提示色和队长色；颜色之外同时保留文本、边框、按钮语义
   和 ARIA。宽屏底部使用不对称 Grid，窄屏回到单列，避免 300px 操作空间不足。

不涉及数据迁移、公开 API、授权模型、资产、服务端状态、部署、Docker 卷或恢复行为。回滚
是删除本次客户端/主题增量并恢复旧 E2E 断言；不会触碰业务数据。

## 5. 跨阶段依赖与兼容约束

- 服务器仍是房间、角色、知识、阶段、选人、投票和任务的唯一权威；客户端颜色与可见按钮
  不能授予权限。
- `ownKnowledge` 不得进入 display、其他玩家 DOM、日志或持久状态；遮盖的自动复位语义
  不放宽。
- Poker 主题、加入买入、牌桌和私牌保持现有行为；新增 Avalon scope 不修改 Poker palette。
- 新状态不能只靠颜色表达；准备、投票、队长、本人、选中、任务规则和当前行动都保留文字、
  边框或 ARIA。
- 中英文、light/dark、300px、键盘、触控、`focus-visible`、唯一内部滚动区和运行时无公网
  资源继续成立。
- 不修改 initial、`change-0.md`、其他 feature 冻结历史、部署接口、正式服务或服务器资源。

   `npm run test:e2e:core`。E2E 自带生产 build/static 检查；若后续修改构建输入则重跑。
3. 运行 `git diff --check`，检查没有生成物、秘密、真实配置或无关文件。
4. 使用本地生产页面进行桌面和 300px 实际浏览器检查；确认 light/dark、操作/队长色、
   加入层、准备区、私密覆盖、选人、投票和任务轨迹。该检查不连接真实 iStoreOS，也不执行
   正式发布。

   `FND-C1-*` 保留。任一新 core、隐私、可访问性、Poker 兼容、构建或恢复问题阻塞。

## 8. 风险、技术决策与修订记录

| 风险 | 控制 |
| --- | --- |
| 私密覆盖误出现在 display 或松开后残留 | 覆盖数据只从 `ownKnowledge + secretVisible` 生成；display 不传；保留全局 pointer/key/visibility/offline/version 复位并做 DOM 断言。 |
| 玩家卡变按钮造成嵌套交互或房主管理冲突 | 只在队长提名阶段把参赛卡渲染为单一原生按钮；该阶段隐藏同卡房主管理按钮，其他阶段恢复原结构。 |
| 颜色层级降低可读性 | Avalon light/dark 分别定义高对比 palette；行动卡内部按钮改用 surface 对比；文本/ARIA 与边框不依赖颜色。 |
| 十个圆点或五任务在 300px 溢出 | 使用等分 Grid、可缩放尺寸和窄屏规则；Chromium/WebKit 300px 检查 document width。 |
| 主题 scope 误改 Poker 或 display | 由 `room.gameType` 判别并在 E2E 比较 scope 与 palette；大厅保持 main。 |
