## 3. 验证与完成条件

### 3.1 core 行为检查

1. 普通页面和固定页面各只有一个纵向滚动所有者；300px 与手机动态视口的下半屏内容可达，
   body 不与固定内部内容区同时滚动。
2. “查看身份”按住期间所有玩家卡统一强调；本人显示精确角色，其他文字只来自合法知识；
   松开与既有安全事件遮盖，display/观众无秘密。
3. 本人确认身份后查看按钮不再使用强调色；手机查看区和操作区左窄右宽并排，二选一按钮
   在右卡上下排列。
4. 五任务无可见序号和标题下总数；未完成项显示人数/失败阈值，完成项只显示成功/失败票数；
   成功/失败实心背景及文字在 light/dark 中可读。
5. 提名队长看到“本局参赛”整卡强调呼吸；减动效保留静态提示。队长/当前任务使用操作
   提示色，本人使用独立色，重合时队长优先。
6. Avalon/Poker 管理按钮默认不可见；房主的触控长按、桌面右键和键盘上下文菜单可打开
   正确目标菜单，普通短触/左键仍执行原业务或无动作，移除确认和在线转让约束保持。

### 3.2 自动化和浏览器门禁

- `npm run lint`
- `npm run typecheck`
- `npm run test:realtime`
- `npm run test:e2e:core`（包含生产 build/static 与 Chromium/WebKit 核心流程）
- `git diff --check`
- 本地生产页面桌面与 300px 的滚动、颜色、手势和几何检查

若 E2E 后修改构建输入，必须重跑受影响的 E2E/build。`test:platform`、`test:avalon`、
`test:poker`、capacity、Docker 和 deploy 默认不运行，因为本阶段不改变服务、规则、容量、
容器或发布接口；实际差异触及这些边界时先修订计划。

`relaxed` 不要求 red-first，但全部 core、隐私、权限、Poker 兼容、可访问性和构建门禁阻塞。
既有 supplemental 异常只有在独立证明无交付影响时才能以 `FND-C2-*` 保留。

## 4. 风险、恢复与修订记录

- 身份状态继续只由本组件 `secretVisible` 控制；任何失败先检查 DOM 是否含越权角色或松开后
  残留秘密。
- 长按手势必须允许正常纵向滚动，普通短触不得被抑制；菜单只对当前仍存在的非本人目标开放。
- 全局滚动改动必须同时检查普通长页面和固定壳层，避免用 body 锁定掩盖内容不可达。
- 当前没有用户 overlap。中断时保留 diff，把 state 保持 `in_progress` 并记录最后通过的
  命令、未完成验收和下一条精确动作；不得 reset、checkout 或 stash。
