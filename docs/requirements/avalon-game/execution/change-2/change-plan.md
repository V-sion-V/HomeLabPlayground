## 3. 影响分析与全局设计

1. 根文档和固定壳层统一使用动态视口高度，并在固定页存在时阻止 body 成为第二滚动所有者；
   普通内容页继续由页面本身承担唯一滚动，不引入嵌套同向滚动区。
2. 身份覆盖先构造规则允许的关系，最后强制写入本人精确角色；revealing 状态独立传给全部
   玩家卡以统一填充，覆盖文字不再用不同整卡背景暴露“亮卡数量”。
3. 底部活动区在所有宽度保留不对称双列；窄屏压缩左侧查看区，并把右侧二选一按钮改为
   纵向 Grid。确认身份后只改变本机查看按钮视觉，不删除合法知识。
4. 任务轨迹继续消费投影中的 `successCount`、`failCount` 与 `AVALON_RULES`，只调整呈现。
   当前项、成功项、失败项分别使用操作提示、成功、危险主题变量及对应高对比文字。
5. 新增共享的上下文菜单手势原语：事件委托识别带目标 ID 的玩家卡；触控长按在移动超过
   阈值时取消并允许页面滚动，桌面右键抑制浏览器菜单，键盘支持 ContextMenu/Shift+F10。
   业务组件仍分别校验房主、本人排除、目标存续和在线转让条件。

不涉及数据迁移、公共 API、服务命令、角色投影、授权模型、资产、SQLite、部署、Docker
或正式服务器。回滚只需恢复客户端组件、样式和 E2E，不触碰业务数据。

## 5. 跨阶段依赖与兼容约束

- 服务端仍是角色、知识、房主、队长、移除、阶段和资产的唯一权威；手势和颜色不授予权限。
- `ownKnowledge` 仍只来自本人有效租约；统一点亮全部卡片不得向 DOM 写入额外角色或知识。
- 身份遮盖继续响应 pointer/key release、blur、visibility、offline、权威版本和阶段变化。
- 上下文菜单通过 portal 显示，保留外部点击、Escape、视口夹持和焦点恢复；移动长按不得
  阻塞正常纵向滚动，提名卡左键/触控选择不得被菜单手势误触发。
- 颜色之外保留本人、队长、成功/失败票数、失败阈值和菜单可读名称；减动效关闭呼吸动画。
- Poker 业务、私牌、牌桌主题及房主命令不变；只替换管理菜单的触发方式。
- 中英文、light/dark、300px、唯一滚动区、`focus-visible` 和运行时无公网资源继续成立。
- 不修改 initial、`change-0.md`、`change-1.md`、其他 feature 历史、部署接口或正式资源。

## 8. 风险、技术决策与修订记录

| 风险 | 控制 |
| --- | --- |
| body 被全局锁定后普通页面无法滚动 | 只让根容器占动态视口，并由普通页面或固定内容区二选一承担滚动；E2E 分别检查大厅、Poker、Avalon 和设置。 |
| 身份统一点亮仍通过背景差异暴露可见对象数 | 所有玩家卡使用同一强调背景，秘密覆盖只叠加文字且不替换整卡色；本人角色最后写入。 |
| 长按与页面滚动、队长选人发生冲突 | 仅非鼠标指针启动定时器，移动超过阈值立即取消；长按触发后抑制一次 click，普通短触仍执行原动作。 |
| 隐藏管理按钮降低键盘可达性 | 玩家卡目标可聚焦并支持 ContextMenu 与 Shift+F10；菜单保留焦点进入、Escape 和恢复。 |
| 实心成功/失败背景在 light/dark 对比不足 | 成功使用主题 success + accentText，失败使用 danger + dangerText，并由计算样式断言和浏览器检查验证。 |
