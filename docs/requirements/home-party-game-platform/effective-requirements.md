## 1. 当前目标与范围

在家庭局域网内提供一个统一、响应式、双语的 Web 聚会游戏平台，使手机和桌面玩家能够免密码进入、组织房间、进行游戏，并把电视或桌面显示器作为只读公共大屏。

当前版本包含平台账户、房间、连接控制、公共大屏、全局设置、赛季、排行榜、守恒型积分经济、SQLite 持久化，以及完整可玩的 2–10 人无上限德州扑克“仅筹码”和“筹码＋牌”模式。玩家牌桌支持 300px 窄屏、可配置花色、连续倒计时和全员准备制结算。部署目标是支持 Docker 的 x86-64 iStoreOS，运行时不得依赖公网。

当前不包含阿瓦隆、狼人杀及其他游戏规则，也不包含密码/账户所有权验证、管理员、互联网威胁模型、匹配、机器人、音视频、原生 App、观战、聊天、成就、付费、跨服务器或完整永久牌局回放。

## 3. 当前流程

1. 设备选择简体中文或英文，以用户名和头像创建/进入账户；设备记录最近账户及偏好。
2. 用户在大厅查看当前/历史排行榜、调整全局设置、创建或加入等待房间；任一活动房间都会阻止新赛季。
3. 房主配置扑克模式、盲注、买入范围和转让时限，玩家买入后就座；公共大屏通过独立只读入口订阅公开投影。
4. 开局后服务端成为唯一权威：管理行动、版本、幂等、资产流水、撤销窗口、自动推进和按角色过滤的状态。
5. 仅筹码模式在线下处理实体牌并由房主录入合格赢家；筹码＋牌模式由服务端发牌、判型并自动分池。
6. 完整结算后，玩家端和大屏持续显示全员筹码净变化与总筹码；真实摊牌额外显示未弃牌摊牌者手牌、赢家和牌型。玩家可在结算层之上打开补码 modal，补码后当前总筹码立即更新；所有仍占座玩家准备、在线且有筹码后才开始下一手。
7. 玩家正常退出、被移除或房间关闭时，剩余牌桌筹码原子兑换回账户；未结算手牌作废时按实际投入退款。
8. 刷新、连接接管、短暂断网和服务重启从 SQLite 权威状态恢复；客户端未确认缓存不会持久化，断线/重启后的玩家需要重新准备。
9. 无房间时，任一登录用户可二次确认创建新赛季；旧赛季排行榜冻结，新赛季按固定基础分初始化。

## 4. 当前数据、接口与状态

- 账户：稳定 ID、规范化唯一用户名、显示用户名、头像、当前赛季账户分数。
- 设备偏好：最近账户、界面语言、静音设置；它们不能作为资产或牌局权威状态。花色预设属于服务器持久化的全局扑克设置。
- 连接租约：每个账户只允许一个当前控制连接；玩家投影要求有效租约，大屏不要求账户。
- 房间：状态、房主、座位、在线状态、模式、盲注、买入上下限、房主超时、准备集合、包含签名净变化和结算后总筹码的公开结果摘要。
- 赛季与排行榜：当前赛季、固定基础分、历史资料/分数/名次/结束时间快照、游戏中冻结显示。
- 资产：账户分数、牌桌筹码、当前下注、主池/边池；所有变化由成组原子流水和稳定命令 ID 支持。
- 牌局：按钮、当前行动者、街道、合法动作、版本、撤销截止、阶段自动推进截止、完整结算准备集合、玩家私有牌和公开牌。
- 投影：大厅公开投影、房间公开投影、当前玩家私有投影和只读大屏投影相互隔离；完整结果可包含全员净变化及经过服务端筛选的真实摊牌摘要。
- 持久化：SQLite 迁移、快照、命令幂等结果、资产流水、截止时间和结果摘要。
- 服务接口：局域网 HTTP 用于账户/大厅/命令和静态资源，WebSocket 用于按角色实时同步，`/healthz` 用于容器健康。

## 5. 当前异常、边界、安全与恢复

- 用户名冲突、重复房间占用、开始后新玩家加入、非法买入/补码/下注/加注/赢家、过期版本和重复命令必须拒绝且不产生部分状态。
- 房主不能越权读取进行中或弃牌者的隐藏牌；公共投影、其他玩家投影和普通日志不得包含非本人进行中手牌。唯一例外是完整结果中真实摊牌、未弃牌玩家的受控公开摘要。
- 断线玩家轮到行动时等待恢复；房主可暂停、终止或移除。房主超时按在线玩家转让，否则作废退款、兑换并关闭。
- 短额大盲仍保持完整大盲开局跟注额；单次短额全押不重新开放加注，多个短额全押累计达到完整加注时重新开放。
- 未跟注超额退回；全押按资格构造主池/边池；重复赢家和不合格赢家在任何资产分配前拒绝。
- 下一玩家确认后撤销失效；撤销与下一操作竞争由权威版本和原子提交决定。
- 完整结算阶段不设置自动下一手截止；断线或零筹码座位会阻塞下一手，离开/移除可解除占座阻塞，重连或补码后仍须有效准备。
- 新结算结果必须保存非负的结算后总筹码；旧结果缺少该字段时仍可加载，界面在当前座位可用时显示实时总筹码，否则显示明确占位而不是推算错误数值。
- 资产不变量失败、持久化失败或进程崩溃必须回滚整个操作；启动时恢复已确认状态并重建易失在线状态。
- Docker 升级必须保留 `/data` 命名卷；回退可停止新容器并使用保留数据。运行时不得依赖公网、CDN、云数据库或外部身份。
- 首版仅面向可信家庭局域网，不建立互联网身份或账户所有权威胁模型；这不削弱隐藏牌、资产、并发和恢复正确性。

## 6. 当前非功能要求

- **NFR-001 响应式交互**：支持常见手机竖屏触控、窄于 320px 的视口和桌面鼠标键盘；页面不产生水平溢出，主要操作不依赖 hover。
- **NFR-002 实时性**：目标局域网内已确认操作及时同步；动画不阻塞权威确认或恢复。
- **NFR-003 容量**：支持约 15 个同时在线账户、1–2 个活动房间及对应大屏。
- **NFR-004 浏览器**：支持当前主流 Chrome、Edge、Safari 和 Android 主流浏览器。
- **NFR-005 离线运行**：部署后核心运行不依赖公网、CDN、外部身份、云数据库或第三方实时服务。
- **NFR-006 部署**：提供 x86-64 iStoreOS Docker 非交互启动和明确持久化数据卷。
- **NFR-007 恢复**：服务重启不得破坏已确认资产、赛季、房间或牌局状态。
- **NFR-008 本地化**：固定文本、错误、按钮和关键音效语义可在简体中文与英文切换。
- **NFR-009 游戏隐私**：进行中、弃牌者和非真实摊牌的隐藏手牌不得进入公共状态、其他玩家或公共大屏投影；真实摊牌完成后只公开未弃牌摊牌者的牌面。
- **NFR-010 可扩展界面**：设置和大厅按游戏分组扩展，后续游戏复用平台账户、房间、赛季和排行榜。
- **NFR-011 可观察性**：结构化日志可诊断启动、持久化、拒绝命令和资产不变量异常，且不记录隐藏牌。
- **NFR-012 动效节奏**：自动推进保留可感知等待与可静音提示音，动画不是规则或资产状态的唯一载体。

## 8. 当前决策

- 交付策略为用户明确选择的 `relaxed`；core、硬门禁和两个 supplemental 验收均已实际通过。
- 首版范围为统一平台加德州扑克；后续游戏复用平台边界，但不在当前实现。
- 目标为支持 Docker 的 x86-64 iStoreOS 家庭局域网；约 15 个在线账户、1–2 个活动房间。
- 账户采用唯一用户名、无密码和设备最近账户；头像为内置头像/emoji。
- 房主控制房间但无隐藏牌特权；新连接接管旧连接；房主超时按在线玩家转让或自动退款关闭。
- 排行榜在入桌时冻结；新赛季要求无房间、归档旧榜并重置全部账户；任一登录用户可发起。
- 扑克采用标准 2–10 人无上限现金桌；仅筹码由房主录入赢家，筹码＋牌由服务端发牌判型。
- 下注采用固定现实面值和缓存确认，不提供数字输入；撤销只在下一玩家确认前有效。
- 公共大屏只读；进行中和弃牌手牌隔离，真实摊牌完成后只显示未弃牌摊牌者牌面；仅筹码模式完全不显示公共牌区域。
- 全局花色预设提供标准和高对比度两种固定映射，并由服务器设置持久化。
- 每手完整结算后不自动开手；所有仍占座玩家都必须准备，断线和零筹码座位会阻塞下一手。
- change-1 依用户要求只执行本地静态、测试、生产构建和真实浏览器验证，不运行 Docker；这不改变既有部署目标。
- 结算总量优先显示仍占座玩家的实时桌上筹码，离座后回退到结算快照；补码不改变已经冻结的本手净变化。
- complete 阶段的补码 modal 挂载在牌桌根级，必须高于结算面板但不得提升整个操作区层级。
- change-2 使用用户明确选择的 `relaxed`，继续本地优先且不运行 Docker。

## 9. 已替换或退役项目

无产品范围被删除。完整结算后的自动下一手定时器和房主手动“下一手”入口已由全员准备协议替换。实现期间用于早期占位的固定演示客户端状态、路由桩浏览器测试以及直接使用 `crypto.randomUUID` 的局域网 HTTP 假设也已被替换；它们从未成为生效产品要求。
