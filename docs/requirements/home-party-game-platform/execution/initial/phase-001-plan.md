## 1. 阶段目标、边界与关联需求

从空白工作区交付一个可在 x86-64 iStoreOS Docker 环境中离线运行的家庭聚会游戏平台，完整实现平台账户、房间、公共大屏、赛季、排行榜、守恒资产、双语和持久化能力，以及“仅筹码”和“筹码＋牌”两种 2–10 人无上限德州扑克模式。

本阶段覆盖 `FR-001`–`FR-057`、`AC-001`–`AC-030` 和 `NFR-001`–`NFR-012`。首版不实现需求明确排除的其他游戏、公网安全、密码、管理员、匹配、机器人、音视频、原生 App、观战、成就、付费或跨服务器能力。

阶段执行前置已验证：schema 3.2 契约有效；需求路径与契约一致；`relaxed` 为用户明确选择；28 个 core 与 2 个 supplemental 验收均已分层；无未决产品问题；无现有代码、迁移、Git 基线或用户工作重叠。

## 4. 风险、恢复与修订记录

### 4.1 风险与恢复

- 资产、命令和房间状态共享事务边界。任务执行时必须先实现幂等与故障回滚测试支持，再扩展扑克写命令；任何不变量异常停止当前任务，不进入下一任务。
- 隐藏牌隔离由服务端投影白名单控制。发现私有字段进入其他玩家、大屏、错误或日志时立即视为阻塞，不允许以 `relaxed` 报告结项。
- 定时推进、房主超时和撤销竞争使用持久化截止时间与房间版本。中断后从数据库与执行状态恢复，不根据浏览器动画推断完成。
- 项目起点无 Git，不能用未记录的重置操作恢复。每个任务开始前在 `execution-state.md` 记录预计范围，结束时记录实际文件；若任务中断，保留当前文件并从状态、定向差异和最近测试结果重建，不删除未知文件。
- 容器回退只替换应用容器并保留 `/data` 卷。首版初始建库无需降级；若实现期间引入会覆盖既有数据的迁移，必须先暂停并把计划修订为 `expanded`，记录备份和恢复门禁。
