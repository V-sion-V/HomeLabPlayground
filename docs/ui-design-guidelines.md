# UI 设计规范

本文件是项目级 UI 约束，适用于后续新增或修改的 modal、弹层、固定管理面板和锚定菜单。产品需求仍决定具体行为；本规范负责统一容器、滚动、层叠、响应式和可访问性实现。

## 1. 基本原则

- 页面只能有一个明确的滚动所有者。固定面板和 modal 的外框不滚动，只有中间内容区滚动。
- 标题顶栏和底部操作区始终可见，不随中间内容移动。
- 外框尺寸不因内容增长、滚动条出现、语言切换或展开/收起内容而跳变。
- 滚动槽必须位于外框边框以内，并由内容区预留；不得覆盖内容、悬空到视口外或挤压相邻布局。
- 浮层的视觉层级不得代替权限判断。按钮可见性和服务端授权必须分别成立。
- 所有新增可见文案同时提供简体中文和英文；不得依赖图标方向、颜色、hover 或动画单独表达含义。

## 2. 固定容器结构

固定管理页面使用共享 `FixedPanel`，modal 使用共享 `Modal` 结构。两者遵循相同的三个区域：

```text
外框（固定尺寸，overflow: hidden）
├─ 顶栏（固定）
├─ 内容区（min-size: 0；唯一纵向滚动区）
└─ 底栏（固定，可省略但不得塞回内容区）
```

实现要求：

- 外框使用 Grid，行定义为 `auto minmax(0, 1fr) auto`。
- 外框及其 Grid 子项必须设置合适的 `min-width: 0` 和 `min-height: 0`，避免长文本撑破布局。
- 外框使用 `overflow: hidden`；内容区使用 `overflow-y: auto`、`overflow-x: hidden` 和 `overscroll-behavior: contain`。
- 内容区使用 `scrollbar-gutter: stable both-edges`。禁止给内容内部再建立同方向滚动区，除非该子区域本身是有明确高度和独立语义的数据视窗。
- 顶栏和底栏各自拥有背景、边界和高于内容区的局部层级。主要保存、确认、取消和危险操作位于底栏或固定顶栏，不放在长内容末尾随内容滚动。
- modal 通过 portal 挂载到 `document.body`，使用 `role="dialog"` 或 `role="alertdialog"`、`aria-modal="true"` 和本地化名称。
- 固定面板使用正确的 `main`/`section` landmark，并通过标题建立可读名称。

## 3. 尺寸与响应式

- 桌面 modal 使用明确的最大宽高；不得依赖内容自然高度无限增长。
- 固定管理页面占可用动态视口高度。应优先使用 `dvh`，同时让内容区承担溢出。
- 视口变窄时，外框按可用宽高收缩，外边距和内边距可降低，但顶栏、内容区和底栏不可消失。
- 管理员首页在宽屏采用通用设置、游戏设置双列；窄屏按通用设置后游戏设置变为单列。
- 最低验证宽度为 300px。页面、固定外框、内容区、选项列表、头像网格和确认层均不得产生页面级横向滚动。
- 可换行的操作组必须允许换行或在窄屏转为纵向；文字区域使用 `min-width: 0` 和适当的换行策略。
- 语言切换、内容展开和滚动条出现前后，固定区域宽度和主要操作位置不得因滚动条发生可见跳变。

## 4. 弹层与层叠

- modal、确认层和锚定菜单通过 portal 离开可能带有 `overflow`、`transform` 或局部 `z-index` 的业务容器。
- 锚定菜单使用 `position: fixed`，以锚点的视口矩形计算位置；优先显示在锚点下方，空间不足时翻转到上方。
- 菜单的左右位置必须夹在可见视口内，并限制最大高度；空间不足时由菜单自身滚动。
- 页面普通内容、座位、牌桌和局部卡片不得覆盖 portal 菜单。层级令牌应集中在共享样式中，不在业务组件内继续堆叠任意数值。
- 打开菜单后焦点进入第一个可用菜单项；`Escape`、外部点击和完成操作都可关闭；锚点仍存在时恢复焦点。
- 锚点被删除、权限失效、房主变化或目标离开时立即关闭菜单。呈现位置变化不得扩大房主权限或绕过服务端校验。
- 产品要求隐藏低频管理动作时，可由同一可聚焦业务卡片触发上下文菜单：触控设备长按、
  桌面精细指针右键，键盘使用 `ContextMenu` 或 `Shift+F10`。普通短触/左键必须保留卡片
  原本操作或无动作；长按在指针移动后立即取消且不得阻塞纵向滚动，触发后必须抑制同一次
  合成 click，避免同时执行卡片主操作。

## 5. 控件与图标

- 导航、展开状态和提交动作使用共享 SVG 箭头，不使用 Unicode 字符箭头。
- 装饰 SVG 设置 `aria-hidden="true"`；承载动作的按钮必须拥有本地化可读名称。
- 自定义下拉框保留可读 label、展开状态、选项角色和键盘操作；选项层不得被父容器裁剪。
- 批量选择提供逐项复选框、全选/取消全选和原生不确定状态。危险操作同时显示选中数量，空选择时禁用。
- range 输入提供 label、整数范围、步长和当前值文本；不得只用滑块位置表达数值。
- 头像选择默认收起，通过当前头像按钮展开；按钮暴露 `aria-expanded`，选项使用可读名称和选中状态。
- 所有交互支持键盘、鼠标和触控，并保留清晰的 `focus-visible`。

## 6. 动效与主题

- 动效只能帮助理解状态，不能成为状态本身。`prefers-reduced-motion: reduce` 下应禁用或极短化非必要动画。
- 颜色必须来自现有主题变量，并在 `light`、`dark` 与相应 `main`/`poker` scope 中验证。
- 危险、成功、禁用和保护状态必须有文字或语义属性，不能只靠颜色。
- 不得引入运行时公网字体、图标、音频、CDN 或其他远程资源。

## 7. 实现检查表

新增或修改固定容器、modal 或菜单时至少检查：

1. DOM 是否只有顶栏、唯一滚动内容区和底栏三个层次。
2. 300px、手机和桌面视口是否都无页面级横向溢出。
3. 长中英文、滚动条出现/消失和内容展开时，外框与操作位置是否稳定。
4. Tab 顺序、可读名称、`focus-visible`、`Escape`、外部点击和焦点恢复是否正确。
5. portal 菜单在视口四边、等待室、活动牌桌和观众条是否可见且不被裁剪。
6. 触控目标、复选不确定状态、range、头像选择和自定义下拉是否可操作。
7. Chromium 桌面和 WebKit 手机核心流程是否通过。
8. 生产构建是否仍不引用运行时公网资源。

共享结构或规则发生变化时，应先更新共享组件和本文件，再迁移具体页面；不得在单一业务页面复制另一套滚动或层叠体系。
